# Flow 생성·회수 자동화 계약

검토된 장면 필드의 원문 추출은 automation/export_scene_prompts.py로 구현했다. 입력·출력과 네 단계 작업 순서는 workflow/13_SCRIPT_TO_PROMPTS.md를 따른다. 실제 이미지가 없는 영상 프롬프트는 DRAFT로 유지하며 추출 성공을 생성·시각 검수 완료로 처리하지 않는다.

이 문서는 구현 요구다. 현재 다운로더가 이를 충족한다는 뜻이 아니다. Chrome 확장 프로그램과 로컬 제작 관리가 대본 자산을 추적하며 이미지 생성→선택·검수→선택 모드의 프레임 입력→사용자가 선택한 Flow 모델로 생성→회수·파일 검증→재시작 복구까지 수행한다. 프롬프트 텍스트 추출은 이 과정의 작은 파생 작업이다.

## 작업 데이터

project_id, episode_id, scene_id, shot_id, keyframe_id는 안정적 식별자다. production_version은 `NOVEL`(기존 무협소설, 기본값) 또는 `WEBTOON_EXPERIMENT`(신규 무협웹툰 실험)로 식별한다. 같은 이야기의 두 버전은 세계관·인물·주요 인과·결말을 공유하되 승인 원고·해시·장면표·프롬프트·편집·제목 자료는 분리한다. 작업 ID와 참조 해시는 버전 안에서 대조하며 같은 장면 번호만으로 다른 버전의 입력을 가져오지 않는다. order_index는 편집 순서, display_number는 표시 번호다. 프롬프트 이미지에 화면용 번호를 그리게 하지 않는다.

작업에는 job_id, kind(image/video), 입력 원고·장면·프롬프트 버전/해시, 참조 이미지 자산 ID, 시작·종료 키프레임 ID/해시, 실제 provider 작업/자산 식별 근거, 선택 후보, 저장 파일, 형식·크기·해상도·길이·해시, 시도 기록, 비용, 오류, 검수 상태를 둔다. 현재 UI에서 얻을 수 없는 provider_job_id는 만들어내지 않는다. 그 경우 실제 작업과의 대응 근거를 별도로 확보하고 대응을 확인할 수 없으면 UNKNOWN으로 남긴다.

이미지 프롬프트 출력은 검수한 장면·keyframe의 확정 필드에서 그대로 추출하며 영상 프롬프트는 실제 선택된 입력 이미지와 샷 동작에서 작성한다. 필요 길이만큼 쓰고 40~120단어를 강제하지 않는다. 공통 움직임 문구로 실제 순간의 행동 설계를 대체하지 않는다. 실제 입력 이미지 또는 TTS가 없으면 영상 지시는 DRAFT다.

다음 신작은 공개 한 화의 총 N이 200 이하이며 내부 네 부를 합친 1~N 번호·순서가 같은 장면을 가리킨다. 버전별 납품 계약은 다음과 같다.

- NOVEL: 시각화 N장면 = Flow 이미지 프롬프트 N개 = Flow 영상 프롬프트 N개. 세 파일의 같은 1~N 번호로 1:1 대응한다.
- WEBTOON_EXPERIMENT: 시각화 N장면 = 기본 이미지 프롬프트 N개 = 모션 편집 계획 N개. Flow 영상은 훅·핵심 장면에서 선택한 K개(K≤N)만 작성하고 원래 장면 번호·ID를 유지한다. 선택 목록을 1~K로 재번호하거나 비선택 장면에 빈 영상 항목을 만들어 N개 완료로 보고하지 않는다. K 미정과 실제 생성 0은 구별한다.

시각화 밖의 후속 컷·A/B/C 영상·무원문 추가 생성 작업을 끼워 넣지 않는다. 분할 변경은 해당 버전 원문 소유권과 모든 파생 파일·선택 Flow 목록을 함께 개정하며 200 상한도 다시 확인한다. 내부 키프레임·재시도 후보·자산 재사용은 별도 추적하며 수량 예외로 쓰지 않는다. 웹툰에서 같은 장면의 크롭·기존 표정 참조 재사용과 새 반응 그림 생성은 구별하고 새 자산의 실제 수량·해시·비용을 별도 기록한다. sidecar 색인에서 버전·번호·원문·기본 이미지·전체 모션 계획·선택 영상의 대응을 검사한다. 기존 승인 작품은 자동 재분할하지 않는다.

새 공개 한 화는 약 80분·4,800초 표시를 계획한다. 8초 클립 200개는 1,600초·26분 40초이며 최종 타임라인 전체의 연속 생성 움직임을 충족하지 않는다. 웹툰에서는 선택 K개의 길이만 생성 클립으로 합산한다. 생성 길이와 최종 표시 시간을 각각 기록하고 이미지 유지·크롭·리프레이밍·타이포·말풍선·필요한 클립 배치를 버전에 맞춰 [장면 정책](04_CONTINUOUS_ANIMATION.md)에 따라 계획한다. 200장면일 때 평균 24초, 약 20~30초 구간은 참고값이며 고정 길이 규칙이 아니다. 자동 연장·일률적인 3배 감속·무한 반복으로 빈 시간을 채우지 않는다. 실제 TTS·편집·재생 검수 전에는 약 80분 영상 완료로 기록하지 않는다.

## 장면에 맞는 간단한 입력과 생성 제한 대응

영상 프롬프트는 선택 참조에 보이는 인물·상태를 기준으로, 그 순간부터 가능한 **비노골적인 표정·시선 또는 한 동작과 한 카메라**를 짧은 긍정문으로 쓴다. 정지 카메라도 하나의 선택이다. 참조에 이미 있는 얼굴·복장 설명과 고유명을 반복해 참조를 대신하지 않는다. 한글 고정명은 등록·장면 대응표에서 유지하고 생성 입력에서는 실제 참조 첨부를 먼저 확인한다. 스타일·환경·조명은 장면에 필요한 만큼만 넣으며 긴 금지 목록이나 모든 장면에 같은 모션을 붙이지 않는다.

피·신체 손상·처형·죽임·살육의 시각 세부는 사건을 전달하는 비노골적인 직전·직후 반응으로 선택한다. 직접적인 충격 대신 긴장한 시선, 멎은 손, 뒤로 물러서는 한 걸음, 사건 뒤 남은 공간처럼 그 장면에 맞는 순간을 고른다. 이미 완료된 행동을 다시 실행시키지 않고 복잡한 합·여러 손의 인계·다수 카메라 변화를 한 클립에 쌓지 않는다. 기존 대본 원문은 그대로 두고 대응표에 화면 해석과 생략한 시각 세부를 기록한다. 등장인물의 실제 나이와 인과·부상·소품 소유권은 유지한다.

별도 TTS를 합칠 장면은 조용한 움직임으로 지시하고 새 대사·발화·비명이나 립싱크를 임의로 만들지 않는다. 음성 생성이 필요한 경우는 선택한 음성 경로와 실제 입력 지원을 따로 확인한다. 간단한 긍정문은 작성 전략이며 공식적인 생성 성공 보장이나 모더레이션 우회법이 아니다. 금지 단어만 지우거나 사건을 암호처럼 바꾸는 방식으로 처리하지 않는다.

실패 시 실제 오류와 입력을 확인한다. 프롬프트 내용, 원본 이미지·참조, 음성, 할당량·비용, 모델·기능·입력 모드 불일치, 일시적 서비스 오류를 나눠 기록한다. 원인을 확인하지 않고 모든 실패를 문구 규제로 단정하거나 같은 유료 작업을 반복하지 않는다. 필요한 장면만 안전한 해석으로 수정한 새 버전을 검수하고, 정상 결과는 보존한다. 허용되는 입력으로 바꿔도 실패가 없다고 약속하지 않는다.

## 브라우저 연결과 캐릭터 등록 재개

Flow 조작을 시작할 때 현재 실행 환경이 지원하는 공식 Chrome·브라우저 연결 기능을 먼저 확인하고, 연결된 탭의 주소와 대상 프로젝트를 대조한다. Windows 앱에서 주소를 확인하지 못한 결과는 그 연결 경로의 제한으로 기록한다. 이 결과만으로 Flow 전체를 사용할 수 없거나 사용자가 설정하지 않았다고 단정하지 않는다. 사용자에게 수동 설정을 요청하기 전에 현재 지원되는 연결의 실제 상태를 확인하고, 연결이 불가능한 경우 확인된 원인과 필요한 조치만 설명한다.

업로드 뒤 이름 없는 캐릭터가 이미 생성되어 있으면 같은 파일을 다시 업로드하지 않는다. 현재 화면에서 확인한 캐릭터 식별자·썸네일·업로드 결과로 해당 항목을 대조하고, 그 캐릭터의 이름 입력과 저장을 이어간다. 일반 미디어 카드와 구별되는 캐릭터 아이콘을 확인하고, 고정 한글 이름과 썸네일이 새로고침 뒤에도 유지되는지 확인한 후 REGISTRATION_VERIFIED로 기록한다.

인물마다 원본 파일·해시, 대상 프로젝트, 업로드·이름 저장·캐릭터 아이콘·새로고침 확인 결과와 마지막 완료 단계를 비공개 체크포인트에 남긴다. 중단 뒤에는 기존 항목과 체크포인트를 먼저 대조해 미완료 단계부터 재개한다. 개별 캐릭터 등록 확인은 장면 입력의 참조 첨부나 전체 생성 자동화 완료를 뜻하지 않는다.

## 실제 실행 순서

캐릭터시트 단계에서 실제 시트 이미지를 프로젝트에 업로드하고 시각화 프롬프트와 같은 한글 고정명으로 저장한다. 단계 07의 등록 완료 근거를 확인한 뒤 아래 생성 작업으로 이어간다. 등록명 문자열 일치, 프로젝트 등록, 개별 생성 입력의 실제 참조 첨부는 각각 검사한다.

1. 대상 Flow 프로젝트, 현재 UI, 모델·화면비·지원 길이·참조 방식·현재 비용을 확인한다. 고정 셀렉터나 미확인 API를 지어내지 않는다.
2. 이미지 작업을 저장한 뒤 참조와 프롬프트를 입력한다. 제출 전 입력 상태를 확인하고 제출 증거와 생성 결과를 연결한다.
3. 실제 이미지를 검사하고 선택 후보를 확정한다. 실패한 후보와 원본 참조를 성공 자산에 섞지 않는다.
4. 영상 작업의 실제 시작 칸에 선택 자산을 연결한다. 시작+종료 모드를 사용할 때는 종료 칸도 연결한다. 모델·길이·프롬프트와 입력 프레임을 확인한 뒤 제출한다.
5. 생성 완료를 확인하고 정확한 자산을 내려받는다. 파일 검증과 시각 검수는 별개 상태로 기록한다.
6. 샷과 실측 음성 타이밍에 맞게 조립한다. 같은 장면의 생성 길이·최종 표시 시간·이미지 유지와 움직임 배치를 각각 확인한다. 실패 구간만 다시 생성하고 관련 편집본을 갱신한다.

## 상태와 재시도

PLANNED→SUBMITTING→SUBMITTED→GENERATING→GENERATED→DOWNLOADING→FILE_VERIFIED→QA_PASSED를 구분한다. 오류는 FAILED, 대응 불명은 UNKNOWN, 입력 변경은 INVALIDATED로 남긴다. 후보가 생성됐다는 사실은 시각 검수 통과가 아니다.

제출 전 로컬 작업을 영속 기록한다. 제출 직후 연결이 끊기면 기존 작업 존재 여부를 먼저 대조한다. UNKNOWN 상태에서 자동 재제출해 중복 유료 생성하지 않는다. 같은 입력의 정상 결과는 해시와 상태를 확인해 재사용한다. 새로고침·브라우저 종료 뒤에도 개별 완료 기록과 입력 버전으로 이어간다.

재시도는 실제 오류 유형에 맞춰 제한 횟수와 점진 대기를 적용한다. 다운로드 재시도와 유료 생성 재시도 횟수를 구분한다. 설정된 예산·재시도 상한 안에서 진행하고, 실패한 구간을 몰래 스틸로 대체하지 않는다. 원격 제한에 따른 대기 중 상태를 보존한다.

## 다운로드와 레거시 복구

기존 프롬프트 컷 번호 모드와 사용자가 확정한 자산 목록에 시작 번호를 부여하는 모드를 구분한다. 레거시 기본은 실제 선택 자산에 연결된 생성 프롬프트 번호다. 큰 이미지와 화면 입력창 번호를 따로 추측해 짝짓지 않는다. 가상 스크롤과 지연 갱신 후에도 자산·프롬프트·번호가 동일 대상을 가리키는지 확인한다.

자산 목록에 ID, 썸네일, 원문 번호, 후보, 저장명을 표시한다. 중복 번호 후보는 선택 규칙과 이유를 기록하고 버전 파일로 보존한다. 실행 중 시작/시험 버튼이 상태를 초기화하지 못하게 한다. 완료 순서·DOM 순서로 번호를 정하지 않는다.

다운로드 작업 ID와 정확한 자산 대응이 있어야 한다. 탭 ID와 referrer가 비었다고 무관한 다운로드를 가로채지 않는다. 파일명 접두사만으로 성공 처리하지 않는다. 목적 경로·실제 파일 형식·정상 디코딩·해상도·길이·해시를 확인한다. 필요한 검사를 확장 프로그램이 못 하면 로컬 검사 단계로 넘기고 FILE_VERIFIED 전 상태에 둔다.

JPEG는 실제 JPEG 파일로, PNG 요청은 실제 변환한 PNG로 저장한다. 확장자만 바꾸지 않는다. UUID 이름만 남았거나 다른 폴더의 동명 파일이면 명명/경로 검증 미완료다. 저장 위치는 브라우저가 지원하는 디렉터리 선택·다운로드 하위 폴더·검증된 로컬 연결 중 실제 가능한 방식으로 구현한다.

기존 파일 자동 덮어쓰기·삭제는 하지 않는다. 복구 폴더와 후보 버전을 사용한다. 처음에는 하나씩 실행하고 완료 확인 후 다음 작업을 진행한다. 대량 처리량은 검증 뒤 조정한다.

## 검증 단계

기존 다운로드 실패 유형을 회귀 대상으로 삼는다: 잘못된 프롬프트 번호, 무관한 다운로드 매칭, 동명 HTML 성공, MIME 불일치, 영속 재개 누락, overwrite, 비동기 화면 혼합, 중복 후보/실행 상태 초기화.

모의 검증 뒤 실제 생성·회수 소량 시험, 3개 정확성, 20개 지속성, 중지/재개·실패 복구 순으로 검증한다. 영상 시험은 공유 프레임 연결과 실제 얼굴·액션 검수를 포함한다. 시험 수치는 구현 확인용 표본이며 전체 품질을 보증하지 않는다. 전체 요청 목록과 실제 파일·QA 통과 목록이 일치해야 배치 완료다.

## 모델 변경과 입력 상태 — 2026-10-09

현재 사용자 선택은 Veo 3.1 - Lite다. 기존 Omni 10초 초안을 그대로 실행하지 않는다. [Flow 공식 지원표](https://support.google.com/flow/answer/16352836?hl=en)를 2026-10-09 확인한 기준에서 Lite의 Frames 첫 프레임 및 첫/마지막 프레임은 4/6/8초, Ingredients와 Extend는 8초로 안내되어 있고 영상 편집 기능은 지원되지 않는다. 8초를 생성 초안의 출발값으로 사용하되 실제 계정 UI·입력 모드·길이·비용을 확인하고 실행한다. 문서 확인은 이번 계획의 실제 UI 확인·생성 실행 근거가 아니다.

공식 Extend 지원이 있다는 사실은 이 계획의 자동 연장 허용이 아니다. NOVEL의 N=N=N≤200 계약이나 웹툰의 선택 K개 계약에서 연장을 숨은 후속 생성·표시 시간 대체로 실행하지 않는다. 필요하면 기존 원문 대응, 작업 수량·추가 비용·편집 길이 영향을 제시해 별도 조정 후 진행한다.

[Flow 입력 안내](https://support.google.com/flow/answer/16353334?hl=en)는 깨끗한 참조와 입력 이미지에 모순되지 않는 텍스트를 안내한다(2026-10-09 확인). 실제 입력에 없는 동작 시작·소품·인물을 프롬프트에서 뒤집지 않고, 필요한 주체·행동·환경·조명·스타일을 그 순간에 맞춘다.

모델 변경 시 원문과 장면 ID를 유지하고 길이·중간 동작·입력 프레임 모드·음성 경로를 개정해 별도 버전으로 저장한다. 시작 이미지 한 장 방식에서는 종료 이미지를 필수로 요구하지 않는다. 기존 대표 이미지가 종료 자세를 묘사했다면 시작 자세와 다를 수 있으므로 대응표로 실제 이미지를 대조한다. 완료된 행동을 되풀이하도록 상충 지시하지 않는다. 기존 정상 이미지를 무조건 다시 생성하지 않는다.

구출·검 뽑기·납검·소품 전달은 물리적 순서와 손 역할을 명시한다. 지원 길이를 맞추려고 확정 대사를 삭제하거나 급하게 낭독시키지 않는다. 실측 TTS 뒤 분할 조정이 필요하면 해당 버전의 시각화·기본 이미지·모션 또는 영상·선택 목록을 함께 개정하고 공개 한 화 200 상한을 다시 확인한다. 의미와 원문 전체를 보존한 조정이 불가능하면 충돌을 보고하며 영상 프롬프트만 늘리지 않는다. 텍스트 검증은 실제 입력 이미지·얼굴·중간 동작·립싱크 검수와 구분한다.
