# Flow 생성·회수 자동화 계약

검토된 장면 필드의 원문 추출은 automation/export_scene_prompts.py로 구현했다. 입력·출력과 네 단계 작업 순서는 workflow/13_SCRIPT_TO_PROMPTS.md를 따른다. 실제 이미지가 없는 영상 프롬프트는 DRAFT로 유지하며 추출 성공을 생성·시각 검수 완료로 처리하지 않는다.

이 문서는 구현 요구다. 현재 다운로더가 이를 충족한다는 뜻이 아니다. Chrome 확장 프로그램과 로컬 제작 관리가 대본 자산을 추적하며 이미지 생성→선택·검수→선택 모드의 프레임 입력→사용자가 선택한 Flow 모델로 생성→회수·파일 검증→재시작 복구까지 수행한다. 프롬프트 텍스트 추출은 이 과정의 작은 파생 작업이다.

## 작업 데이터

project_id, episode_id, scene_id, shot_id, keyframe_id는 안정적 식별자다. order_index는 편집 순서, display_number는 표시 번호다. 프롬프트 이미지에 화면용 번호를 그리게 하지 않는다.

작업에는 job_id, kind(image/video), 입력 원고·장면·프롬프트 버전/해시, 참조 이미지 자산 ID, 시작·종료 키프레임 ID/해시, 실제 provider 작업/자산 식별 근거, 선택 후보, 저장 파일, 형식·크기·해상도·길이·해시, 시도 기록, 비용, 오류, 검수 상태를 둔다. 현재 UI에서 얻을 수 없는 provider_job_id는 만들어내지 않는다. 그 경우 실제 작업과의 대응 근거를 별도로 확보하고 대응을 확인할 수 없으면 UNKNOWN으로 남긴다.

이미지 프롬프트 출력은 keyframe의 확정 필드에서 그대로 추출하며 영상 프롬프트는 실제 선택된 입력 이미지와 샷 동작에서 작성한다. 필요 길이만큼 쓰고 40~120단어를 강제하지 않는다. 공통 문자열 삽입이나 짧은 움직임 지시로 실제 행동 설계를 대체하지 않는다.

scene 수, shot 수, 고유 keyframe 수, image job 수, video job 수는 서로 같을 필요가 없다. 공유 프레임·재사용 이미지·복수 클립을 허용한다. 완료 검사는 필요한 작업 집합과 검증된 결과의 대응 및 타임라인 충족으로 한다. 최종 파생 텍스트에는 sidecar 색인을 두어 빈 줄 개수만으로 매핑을 판단하지 않는다.

## 실제 실행 순서

1. 대상 Flow 프로젝트, 현재 UI, 모델·화면비·지원 길이·참조 방식·현재 비용을 확인한다. 고정 셀렉터나 미확인 API를 지어내지 않는다.
2. 이미지 작업을 저장한 뒤 참조와 프롬프트를 입력한다. 제출 전 입력 상태를 확인하고 제출 증거와 생성 결과를 연결한다.
3. 실제 이미지를 검사하고 선택 후보를 확정한다. 실패한 후보와 원본 참조를 성공 자산에 섞지 않는다.
4. 영상 작업의 실제 시작 칸에 선택 자산을 연결한다. 시작+종료 모드를 사용할 때는 종료 칸도 연결한다. 모델·길이·프롬프트와 입력 프레임을 확인한 뒤 제출한다.
5. 생성 완료를 확인하고 정확한 자산을 내려받는다. 파일 검증과 시각 검수는 별개 상태로 기록한다.
6. 샷과 음성 타이밍에 맞게 조립한다. 실패 구간만 다시 생성하고 관련 편집본을 갱신한다.

## 상태와 재시도

PLANNED→SUBMITTING→SUBMITTED→GENERATING→GENERATED→DOWNLOADING→FILE_VERIFIED→QA_PASSED를 구분한다. 오류는 FAILED, 대응 불명은 UNKNOWN, 입력 변경은 INVALIDATED로 남긴다. 후보가 생성됐다는 사실은 시각 검수 통과가 아니다.

제출 전 로컬 작업을 영속 기록한다. 제출 직후 연결이 끊기면 기존 작업 존재 여부를 먼저 대조한다. UNKNOWN 상태에서 자동 재제출해 중복 유료 생성하지 않는다. 같은 입력의 정상 결과는 해시와 상태를 확인해 재사용한다. 새로고침·브라우저 종료 뒤에도 개별 완료 기록과 입력 버전으로 이어간다.

재시도는 실제 오류 유형에 맞춰 제한 횟수와 점진 대기를 적용한다. 다운로드 재시도와 유료 생성 재시도 횟수를 구분한다. 설정된 예산·재시도 상한 안에서 진행하고, 실패한 구간을 몰래 스틸로 대체하지 않는다. 원격 제한에 따른 대기 중 상태를 보존한다.

## 다운로드와 레거시 복구

기존 프롬프트 컷 번호 모드와 사용자가 확정한 자산 목록에 시작 번호를 부여하는 모드를 구분한다. 레거시 기본은 실제 선택 자산에 연결된 생성 프롬프트 번호다. 큰 이미지와 화면 입력창 번호를 따로 추측해 짝짓지 않는다. 가상 스크롤과 지연 갱신 후에도 자산·프롬프트·번호가 동일 대상을 가리키는지 확인한다.

자산 목록에 ID, 썸네일, 원문 번호, 후보, 저장명을 표시한다. 중복 번호 후보는 선택 규칙과 이유를 기록하고 버전 파일로 보존한다. 실행 중 시작/시험 버튼이 상태를 초기화하지 못하게 한다. 완료 순서·DOM 순서로 번호를 정하지 않는다.

다운로드 작업 ID와 정확한 자산 대응이 있어야 한다. 탭 ID와 referrer가 비었다고 무관한 다운로드를 가로채지 않는다. 파일명 접두사만으로 성공 처리하지 않는다. 목적 경로·실제 파일 형식·정상 디코딩·해상도·길이·해시를 확인한다. 필요한 검사를 확장 프로그램이 못 하면 로컬 검사 단계로 넘기고 FILE_VERIFIED 전 상태에 둔다.

JPEG는 실제 JPEG 파일로, PNG 요청은 실제 변환한 PNG로 저장한다. 확장자만 바꾸지 않는다. UUID 이름만 남았거나 다른 폴더의 동명 파일이면 명명/경로 검증 미완료다. 저장 위치는 브라우저가 지원하는 디렉터리 선택·다운로드 하위 폴더·검증된 로컬 연결 중 실제 가능한 방식으로 구현한다.

기존 파일 자동 덮어쓰기·삭제는 하지 않는다. 복구 폴더와 후보 버전을 사용한다. 처음에는 하나씩 실행하고 완료 확인 후 다음 작업을 진행한다. 대량 처리량은 검증 뒤 조정한다.

## 검증 단계

기존 다운로드 실패 유형을 회귀 대상으로 삼는다: 잘못된 프롬프트 번호, 무관한 다운로드 매칭, 동명 HTML 성공, MIME 불일치, 영속 재개 누락, overwrite, 비동기 화면 혼합, 중복 후보/실행 상태 초기화.

모의 검증 뒤 실제 생성·회수 소량 시험, 3개 정확성, 20개 지속성, 중지/재개·실패 복구 순으로 검증한다. 영상 시험은 공유 프레임 연결과 실제 얼굴·액션 검수를 포함한다. 시험 수치는 구현 확인용 표본이며 전체 품질을 보증하지 않는다. 전체 요청 목록과 실제 파일·QA 통과 목록이 일치해야 배치 완료다.

## 모델 변경과 입력 상태 — 2026-09-08

현재 사용자 선택은 Veo 3.1 Lite다. 기존 Omni 10초 초안을 그대로 실행하지 않는다. Flow 공식 지원표 확인 기준 Lite의 시작 프레임 및 시작+종료 프레임 영상은 4/6/8초를 지원한다. 8초를 초안 출발값으로 사용하되 실제 UI와 음성 길이에 맞춰 확정한다. 근거: https://support.google.com/flow/answer/16352836?hl=en (2026-09-08 확인).

모델 변경 시 원문과 장면 ID를 유지하고 길이·중간 동작·입력 프레임 모드·음성 경로를 개정해 별도 버전으로 저장한다. 시작 이미지 한 장 방식에서는 종료 이미지를 필수로 요구하지 않는다. 기존 대표 이미지가 종료 자세를 묘사했다면 시작 자세와 다를 수 있으므로 대응표로 실제 이미지를 대조한다. 완료된 행동을 되풀이하도록 상충 지시하지 않는다. 기존 정상 이미지를 무조건 다시 생성하지 않는다.

구출·검 뽑기·납검·소품 전달은 물리적 순서와 손 역할을 명시한다. 지원 길이를 맞추려고 확정 대사를 삭제하거나 급하게 낭독시키지 않는다. 실측 TTS에 따라 추가 클립·연장·편집을 결정한다. 텍스트 검증은 실제 입력 이미지·얼굴·중간 동작·립싱크 검수와 구분한다.
