# 음성·편집·납품·운영

## 단계 흐름

자료 인수→공통 시즌/설정·공개 편성 설계→버전별 본문 집필→인과/발화·공개 회차 통합 검수→원고 버전 확정→캐릭터 자료→장면 분할·시각화→기본 이미지와 음성→버전별 영상/모션·말풍선 편집→전체 QA→제목·썸네일·설명→공개 회차 완성→필요 시 시즌 몰아보기.

캐릭터 자료는 기존 화풍·고정명을 유지한다. 소설판 NOVEL은 시각화 N=이미지 N=Flow 영상 N으로 납품한다. 웹툰판 WEBTOON_EXPERIMENT는 시각화 N=기본 이미지 N=모션 계획 N과 선택 Flow 영상 K≤N으로 구성한다. 두 버전 모두 N≤200이며 [두 버전 제작 지침](08_TWO_VERSION_PRODUCTION.md)에 따라 원고·해시·장면·음성·편집·포장 자료를 분리한다.

장면 구상과 캐릭터 자료 준비는 집필 중에도 가능하다. 최종 생성 길이와 타임라인은 음성과 의도한 무음 액션 길이를 기준으로 확정한다. 필수 입력이 없는 단계만 대기한다.

## 원고 출력과 TTS

본문은 일반 서술의 나레이션과 `[화자명|감정]"대사"`로 작성한다. 감정 목록과 FIRM 사용은 현행 집필 지침을 따른다. 지문·화자명 콜론·연기 괄호로 된 영화 각본 형식으로 임의 변경하지 않는다. 문장/발화 ID는 본문 밖의 구조화 데이터에 연결한다. 실제 TTS 어댑터에서는 화자·감정 제어 정보를 분리해 각 엔진이 지원하는 입력으로 변환한다.

기존 TTS 소스를 받은 뒤 엔진·보이스 ID·감정 지원·속도·샘플레이트·비용·캐시·재시도 동작을 확인한다. 소스가 없는데 연결 완료라고 하지 않는다. 낭독 대상에서 제목·청크 표식·카메라·제어 태그·CTA/END를 제외한다. 발음 교정은 별도 pronunciation map으로 기록하고 문학 정본을 몰래 바꾸지 않는다.

utterance_id↔원문 버전↔음성 파일↔실측 길이↔정렬 시각을 유지한다. 화자에 맞는 연기와 대화의 호흡을 실제로 듣는다. 음성 재생성 시 해당 발화 이후의 영향 타이밍과 자막·샷 배치를 다시 계산한다.

다음 신작은 각 공개 회차의 목표·최종 실측 기준이 4,800초다. 내부 네 부×약 20분은 집필 계획이며 실제 음성·동시에 진행되는 영상·의도한 침묵/액션으로 최종 타임라인을 측정한다. 겹치는 음성과 영상을 두 번 더하거나 생성 클립 수만으로 80분 달성을 표시하지 않는다. 중요한 대사를 줄여 클립에 맞추거나 반복 설명·무의미한 정지·과도한 감속으로 길이를 늘리지 않는다. 계획·예상·실측을 구별하며 기존 작품에는 그 작품의 사용자 계획을 적용한다.

## 엔진 선택과 재생성 비용

행동과 공간을 설명하는 일반 서술도 낭독 본문이다. 영상으로 보일 것이라는 이유로 이를 비낭독 지문으로 전환해 분량·비용을 계산하지 않는다. 대사는 현행 집필 지침에 따라 공방 전체의 포인트 효과로 판단한다. 배역별 엔진·보이스·연기 설정을 샘플로 비교하고, 실제 선택 전에는 확정된 것으로 기록하지 않는다.

Flow의 Frames/Ingredients별 음성 지원을 구별하고 외부 음성과 입모양의 일치를 별도로 검수한다. 현재 확인한 기능·요금은 [음성 선택 기록](../references/VOICE_OPTIONS_2026_09.md)에 있다. 가격표와 계정 구독의 실제 청구를 구별한다.

정상 음성을 보존하고 수정·실패 구간만 다시 생성한다. 캐시에는 엔진·모델·보이스·텍스트·발음·연기·속도를 반영한다. API 요청을 발화 ID마다 무조건 하나로 쪼개지 않으며 짧은 연속 대화의 호흡을 보존한다.

## 연속 애니메이션과 소리

소설판은 원고의 행동과 연기를 장면별 영상으로 구현하고 얼굴·무기·동작 경계를 재생 확인한다. 웹툰판은 이미지 안의 시선·표정·반응과 말풍선·성우·화면 이동으로 사건을 전개하며 생성 영상은 선택된 훅·핵심 행동에 쓴다. 의도적인 정적 연출은 가능하지만 실패 은폐나 80분을 채우기 위한 무한 반복으로 사용하지 않는다. N≤200일 때 80분의 평균 장면 길이는 24초 이상이다. 짧은 Flow 클립 하나로 그 장면의 발화 전체가 해결됐다고 간주하지 않고 실제 음성 길이와 연출 계획을 대조한다.

음악·효과음·대사 음원을 별도 트랙으로 관리한다. 원고 없는 말을 영상에 자동 생성해 넣지 않는다. 캐릭터 입모양·네이티브 음성 생성이 필요한 샷은 실제 모델/입력 모드에서 지원 여부와 선택한 음성의 동기화를 확인한 후 사용한다. 별도 음성 제작이 기본이며 생성 오디오의 보존/제거 여부를 명시한다. 지원 확인 없이 음성 참조나 립싱크가 된다고 표시하지 않는다.

사용 권한이 있는 음악·효과음을 사용하고 음성 가독성·음량 변화·잡음·전환을 확인한다. 자막은 실제 발화·시각과 맞추며 감정 태그와 관리 문구를 노출하지 않는다.

## CapCut과 최종 렌더

현재 설치 버전과 지원되는 가져오기/프로젝트/UI 연결을 확인한다. 확인되지 않은 프로젝트 포맷을 써 놓고 자동 편집 완료라고 하지 않는다. 직접 연결이 불가능하면 재생 가능한 초벌 MP4, 음성 트랙, 자막, 자산·컷 목록을 제공하고 남은 수동 작업을 명시한다. 이는 완전 자동 CapCut 구현과 구분한다.

최종본 전체의 순서·길이·의도하지 않은 검은 화면·멈춤·얼굴 변형·소품·자막·음성을 검사한다. 알려진 차단 오류는 해결하며 미검사 범위를 통과로 기록하지 않는다. 설정/원고/자산/렌더 버전과 QA 결과를 묶는다.

## 제목·썸네일·설명

기존 포장 요구는 유지한다. 실제 썸네일 이미지 3안과 제목을 대응시키고 본문 사건 근거를 기록한다. 의문형·직설형·실제 숫자/역전형을 비교하되 허위 숫자를 만들지 않는다. 제목 길이와 썸네일 문구는 가독성 기준으로 확인하며 창작 본문의 제약으로 넘기지 않는다.

썸네일·제목·설명란의 회차와 최종화·완결 표기는 사용자가 정한 시즌 총회차 및 현행 제작 배분과 대조한다. 원본 시놉시스의 마지막 서사 단위 번호를 제작 최종화의 근거로 대체하지 않는다. 배분 충돌이 발견되면 발행 자료를 미확정으로 표시하고, 기존 승인 대본을 보존한 채 필요한 재배분 범위를 제시한다.

신작 공개 포장은 1~4화 기준이며 4화만 최종화다. 내부 16부는 공개 네 화의 챕터로 관리하고 별도 업로드 16화나 공개 최종 16화로 표기하지 않는다. 긴 영상에서도 첫 두 줄·제목·썸네일은 그 한 편의 가장 강한 사건과 궁금증을 담는다. 실제 제목을 썼다는 이유로 성과 개선을 확정하지 않는다.

설명란 12구획: 첫 두 줄 훅, 본문 포인트, 실제 5~8개 타임라인, 제작 안내, 권리 안내, 등장인물, 무공/용어, 관련 영상, 이전 작품, 몰아보기, 해시태그 12개, 댓글 질문. 최종 고정 문구는 '🗡️ 무협스튜디오 — 강호는 멈추지 않는다.' 한 번이다. 미확인 URL·제작 고지·타임스탬프를 지어내지 않는다. 흥행이나 알고리즘 효과를 보장하지 않는다.

타임라인 구획은 항상 작성한다. 음성·편집본이 없으면 대본과 가능한 낭독 샘플에서 추정한 5~8개 주요 챕터를 예상 타임라인으로 명시하고, 최종 영상이 나오면 해당 공개 회차의 00:00부터 실측 시각으로 교체한다. 샘플이 없으면 가정과 산정 근거를 기록한다. 내부 부마다 시간을 00:00으로 되돌리거나 고정 20분 간격을 실제 시각처럼 쓰지 않는다. 공개 업로드 전에 각 버전의 실측 대응을 확인한다.

CTA/END는 현행 출력 계약의 위치에 두는 무음 제작 표식이다. 공개 회차 전체에 한 벌을 두며 내부 부·기술 청크에서 반복하지 않는다. TTS에서 표식을 제외한다. 중간 공개 회차의 End는 다음 전개를 기대하게 하는 직접 대사, 최종 공개 회차는 이야기를 마무리하는 직접 대사로 끝낸다. 뒤에 낭독 나레이션을 덧붙이지 않는다. 확정 대본은 납품 단계에서 임의 재작성하지 않는다. 공개 업로드는 현재 사용자가 요청한 범위에서 별도 실행한다.

## 저장·버전·복구

프로젝트 안에 canon, script, memory, characters, shots, keyframes, jobs, voice, edit, metadata, reports, exports를 둔다. UTF-8 .md/.json/.jsonl과 실제 미디어를 로컬 정본으로 사용한다. 매 작업의 입력 버전·출력 해시·마지막 완료/다음 작업을 저장한다. 집필 단계 상태는 NOT_STARTED, IN_PROGRESS, NEEDS_REVIEW, ACCEPTED, INVALIDATED, FAILED다. 사용자 확정은 accepted_by:user, 자동 검수 확정은 accepted_by:workflow_review로 구분한다.

문장 변경→해당 사실·기억·발화·샷·자막·편집 영향, 키프레임 변경→이를 공유하는 영상, 음성 변경→영향 타이밍, 제목 변경→포장 QA를 무효화한다. 파생 목록은 다시 만들되 영향 없는 유료 자산까지 전부 재생성하지 않는다.

Google Docs는 요청 시 정본의 표시/공유 수단으로 사용한다. 대상 문서·탭·개정을 확인하고 배치 쓰기 후 읽어 확인한다. 성공 여부 불명인 쓰기는 먼저 중복을 확인한다. 문서 용량 문제로 본문을 축약하지 않는다. 원본 파일/연속 문서 등의 보존 경로를 사용하고, 한 문서 고정 요청과 충돌하면 그 지점만 설명한다.

신작은 공개 회차별·버전별 문서에 대본·시각화·이미지·Flow 영상 또는 웹툰 모션/말풍선·제목/설명/타임라인·캐릭터시트를 연결한다. 내부 부별 자료는 챕터와 원문 ID로 대응시키며 다른 회차·버전 문서를 단순 복사하지 않는다. 탭마다 공개 회차 ID·제작 버전·대본 버전/해시·원문 범위를 확인하고 쓴 뒤 읽어 대조한다.

공개 저장소에 미공개 원고·이미지·계정·서명 URL을 넣지 않는다. 이 저장소는 사용자가 지속적인 커밋·푸시 관리를 요청한 공통 워크플로우 저장소다. workflow/12_THREE_PC_SYNC.md에 따라 검증된 변경을 main에 통합·푸시하고 원격 커밋을 확인한다. 로컬 개정 완료를 원격 반영 완료로 표시하지 않는다.

## 몰아보기와 완료

공개 총회차를 모두 완성한 뒤 별도 시즌 통합본을 요청받으면 중복 도입·요약·카드만 골라 편집한다. 신작은 버전마다 80분 네 편의 계획이므로 별도 시즌 몰아보기를 필수 납품으로 만들지 않는다. 본편의 원인·대사·감정 장면을 중복으로 오인해 자르지 않는다. 전체 자막·음량·챕터를 다시 계산하고 실제 통합본을 검사한다.

회차 납품: 원고/정본, 샷·키프레임·작업 연결, 실제 이미지·영상, 음성·자막, 최종 재생 파일, 썸네일/제목/설명, QA와 재개 기록. 작업 문서·모의 테스트·실제 생성·전체 렌더 검증은 각각 완료 여부를 보고한다.
