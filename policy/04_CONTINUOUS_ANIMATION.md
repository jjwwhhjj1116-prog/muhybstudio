# 캐릭터와 연속 영상의 장면 분석

대본 → 캐릭터시트 → 장면 분석·시각화 → Flow 파생 프롬프트의 현행 절차는 workflow/13_SCRIPT_TO_PROMPTS.md를 따른다. 조선시대 갓·삿갓·관복과 만화책 페이지 테두리·분할 격자는 이 채널의 강호 시각화에서 금지한다. 문파별 외형과 복식은 작품 정본과 캐릭터시트에 맞추며 실제 이미지에서도 검사한다.

다음 신작의 기본 편성은 내부 16부·각 약 20분, 네 부를 합친 공개 한 화 약 80분·4,800초, 공개 총 4화다. 시각화는 공개 한 화 전체를 대상으로 하며 **각 제작 버전의 총 N은 200 이하**다. 기존 승인 작품·장면표·자산은 이 기준으로 자동 재분배하지 않는다.

## 같은 이야기의 두 제작 버전

`NOVEL`은 기존 **무협소설 버전**, `WEBTOON_EXPERIMENT`는 신규 **무협웹툰 실험 버전**이다. 기본값은 NOVEL이며 새 실험이 기존 방식을 교체하지 않는다. 같은 작품의 세계관·인물·주요 인과·결말은 공유하되, 버전별 승인 대본·해시·장면표·프롬프트·편집 계획·제목·설명란은 분리한다. 장면 번호가 같아도 다른 버전의 자산을 해당 입력이라고 가정하지 않는다. 재사용 자산은 실제 파일·해시와 역할을 연결한다.

- NOVEL: **시각화 N = 이미지 프롬프트 N = Flow 영상 프롬프트 N, N≤200**. 같은 1~N 번호로 대응한다.
- WEBTOON_EXPERIMENT: **시각화 N = 기본 이미지 프롬프트 N = 모션 편집 계획 N, N≤200**. Flow 영상은 훅·핵심 장면 중 선택한 K개, K≤N이며 원래 장면 ID와 번호를 유지한다. 선택 목록을 1~K로 재번호하거나 나머지를 빈 영상 프롬프트로 채워 200개를 만든 것처럼 보고하지 않는다. K가 정해지지 않았으면 미정으로 기록한다.

웹툰 버전의 나머지 장면은 선택 이미지·표정 참조·크롭·리프레이밍·타이포·말풍선과 별도 성우 음성의 편집 계획으로 구성한다. 컷이나 말풍선 수가 시각화 N과 같아야 한다는 규칙은 없다. 편집 구도·좌표·말풍선·음성·모션 기술 설명은 낭독 대본 밖의 별도 자료에 쓴다. 실험 계획과 실제 편집·영상 완성은 구별한다.

## 화풍과 캐릭터

상세 시트의 필수 규격은 [캐릭터 이미지 단계](../stages/07_CHARACTER_IMAGE.md)를 따른다. 최상단 한글 이름·전신 3면·표정 6종·동작 5종·소품 상세·Medium 품질을 생략하지 않는다. 아래 문자·격자 금지는 장면 이미지와 등록용 참조에 적용하며, 이름과 여러 칸이 필요한 상세 자료판에는 적용하지 않는다.

기존 웹툰 이미지의 화풍·인물 디자인을 유지한다. 역사 참고 영상의 회화풍으로 바꾸거나 얼굴 문제를 화풍 탓으로 단정하지 않는다. 기존 원본을 받은 뒤 특징과 실제 사용 상태를 등록한다. 새 각도·표정·동작 이미지는 기존 디자인에 맞춰 만들며 재디자인으로 대체하지 않는다.

인물 설정 자료판은 제작진 확인과 사용자 요청에 따른 Flow 프로젝트 캐릭터 등록에 사용한다. 실제 시트 업로드·이름 입력·저장 확인까지 stages/07_CHARACTER_IMAGE.md의 완료 기준을 따른다. 개별 장면의 생성 참조는 별도로 선택한다. 단일 생성 참조는 한 파일에 한 인물·한 각도·한 상태로 정리하고 문자·격자를 넣지 않는다. 전신만 고집하지 않고 얼굴 연기가 필요한 샷에는 얼굴이 충분히 보이는 참조를 선택한다. 각도별 참조를 만들되 모든 샷에 모든 이미지를 첨부하지 않는다. 부상·의상·변장의 지속 상태는 별도 state_id로 추적한다.

조연도 여러 샷에서 같은 얼굴로 이어져야 하면 실제 참조를 만든다. '보조 인물 이미지 0'은 폐기한다. 군중 등 개별 정체성이 중요하지 않은 경우 외형·의상 앵커를 쓴다. 인물 수를 무조건 3명으로 제한해 사건을 바꾸지 않으며, 다인 장면은 시선과 공간 관계를 알아볼 수 있게 연출한다.

등록명 문자열만 썼다고 이미지 참조가 연결된 것으로 보지 않는다. 현재 Flow의 실제 자산 첨부/참조 방식과 입력 상태를 확인한다. 긴 공통 수식어·불꽃·입자·바람을 모든 장면에 자동 추가하지 않는다. 기준 화풍과 해당 장면에서 필요한 정보만 사용한다. 시트·격자 구도를 유도하는 문구는 장면 생성 프롬프트에 넣지 않는다.

## 원고에서 샷으로

각 버전의 대본 확정 뒤 장면 분할을 먼저 하고, 분할한 대본 장면에 맞춰 시각화 프롬프트를 만든다. 문장에는 안정적인 sentence_id를 부여하고 원문·화자를 보존한다. NOVEL은 한 장면에 이미지·영상 프롬프트 하나씩, 웹툰은 기본 이미지·모션 편집 계획 하나씩 대응한다. 여러 발화는 묶을 수 있으나 새 생성 후속 컷으로 장면 수를 숨기지 않는다. 동작을 분리할 때는 해당 버전의 원문을 새 시각화 장면에 재배정하고 모든 파생 대응과 선택 Flow 목록을 함께 갱신한다.

초기 장면 분할은 같은 장소·시간·시점과 이어지는 행동의 약 2~3문장을 한 의미 묶음으로 잡는다. 고정 문장 수나 영상 생성 길이 공식이 아니다. 한 문장마다 자동 분할하지 않으며 실제 낭독 호흡·대사 사이의 쉼·사건의 시작과 결과를 확인해 조정한다. 공개 네 부의 번호는 1~N으로 이어지고 내부 부가 바뀌어도 다시 시작하지 않는다.

2~3문장 묶음으로 전체 원문을 담으면 200장면을 넘는 경우, 먼저 같은 장소·시간·행동에서 인접한 묶음을 의미가 유지되는 범위로 통합한다. 이때 문장 수가 늘어난 이유와 대표 순간을 기록한다. 다른 장소·시간·상태를 한 이미지에 겹치거나 원문을 삭제·요약하거나 거대한 문장으로 다시 써 수량을 맞추지 않는다. 전체 원문 소유권과 의미를 보존하면서 200 이하로 묶을 수 없으면 충돌 구간·필요 장면 수·가능한 조정안을 남겨 사용자 조정을 요청한다. 임의로 200을 초과한 목록을 완성본으로 납품하지 않는다.

샷과 발화는 시간 관계로 연결한다. 한 장면에 여러 발화가 있을 수 있다. 긴 문장의 분할은 원문 위치를 보존한 절 경계에서 하며 글자·구두점·화자·감정 태그를 바꾸거나 중복 낭독하지 않는다. 화면 길이를 맞춘다는 이유로 시각화에 없는 무음 액션 샷을 자동 추가하지 않는다. 원문 구간 포함 여부와 실제 타임라인의 의도하지 않은 공백을 각각 검사한다.

샷마다 다음을 기록한다: shot_id, scene_id, order_index, 연결 발화·음성 시각, 관객이 알아야 할 사건/감정, 장소·시간·인물 상태, 시작 상태, 동작의 진행, 종료 상태, 시작/종료 이미지 ID와 해시, 카메라·시선·이동 방향, 다음 샷 연결 방식. 편집 순번은 바뀔 수 있지만 식별 ID는 재번호하지 않는다.

## 생성 길이와 최종 화면 표시 시간

현재 영상 초안은 Veo 3.1 - Lite의 8초 클립을 출발값으로 삼되 실행 전 실제 UI의 모델·입력 모드·지원 길이를 확인한다. 한 장면의 생성 클립 길이와 그 장면이 최종 편집에서 표시되는 시간은 별개다. 실제 TTS가 없으면 표시 시간도 예상 계획이다.

4,800초를 200장면에 배정하면 평균 표시 시간은 24초다. 20~30초 정도의 고른 구간은 계획 참고이며 모든 장면을 같은 길이로 강제하지 않는다. 짧은 대사·반응은 짧게, 긴장과 감정의 지속은 원문과 음성에 맞게 배정한다. **8초 × 200클립은 1,600초, 26분 40초**이므로 이를 약 80분 전체의 연속 생성 애니메이션으로 보고하지 않는다.

같은 번호 안에서 선택 이미지의 유지, 크롭·리프레이밍, 필요한 8초 움직임의 배치를 편집 계획에 적는다. 웹툰은 선택 K개에만 생성 클립을 배치하고 나머지 장면에도 모션 편집 계획을 둔다. 이런 편집 변화를 새 A/B/C 생성 컷이나 추가 영상 작업으로 숨기지 않는다. 움직임이 부족하다고 자동 Extend·일률적인 3배 감속·무한 반복을 실행하지 않는다. 별도 생성이나 연장이 필요하면 수량·비용·원문 대응·편집 영향을 검토해 사용자 조정 뒤 새 계획으로 관리한다. 이미지와 움직임으로 원문의 청취를 동행하는 영상 계획이며 실제 편집·재생 검수 전에는 전체 시간 충족을 확정하지 않는다.

웹툰의 장면 안 반응 컷은 승인 표정 참조의 재사용이나 같은 이미지의 크롭으로 설계할 수 있다. 새 표정·반응 그림이 필요하면 별도 자산 ID·생성 여부·원문 대응·파일·해시·수량·비용을 남긴다. 새 그림을 참조 재사용이라고 보고하거나 기본 이미지 N과 추가 자산 수를 섞지 않는다. 새 그림이 별도 사건·시간을 맡으면 장면표를 재검토하고 전체 원문 소유권·200 상한을 확인한다. 좌우 반전으로 손 역할·부상·흉터를 뒤집지 않는다.

두 버전의 생성용 기본 이미지는 깨끗한 16:9 단일 강호 화면이다. 웹툰의 말풍선·타이포·선택적인 판넬 경계는 후편집 오버레이로 관리한다. 생성 이미지에 원치 않는 만화책 페이지 테두리·분할 격자·글자를 그리게 하는 것과 구별한다. 한국어 오버레이의 글자·화자·독해 순서·가독성·얼굴 가림을 실제 화면에서 검사하고 같은 대사를 말풍선과 자막에 중복 노출하지 않는다.

## 시작·종료 프레임 연결

같은 행동을 이어가는 샷은 실제로 선택한 키프레임 자산을 공유한다. K01→K02, K02→K03처럼 연결하며 같은 이미지 설명문만 복사해 서로 다른 그림을 연결점으로 사용하지 않는다. 키프레임은 해당 순간의 상태이고 영상 프롬프트는 선택 입력에서 시작하는 행동이다. 시작+종료 모드에서는 두 실제 이미지 사이의 행동을 맞추고, 시작 이미지 단독 모드에서는 종료 자산을 억지로 요구하지 않는다. 이미지를 생성한 뒤 실제 입력 그림을 보고 영상 지시를 작성·수정한다.

달리기·회전·검술은 대본의 동작과 감정에 필요한 단계별 프레임을 설계한다. 모든 동작을 한 클립에 압축하거나 반대로 모든 동작을 기계적으로 잘게 자르지 않는다. 인물의 의도와 액션의 흐름이 보이는 길이를 선택한다. 대화 상대 전환, 반응, 시간·장소 전환은 필요에 따라 컷으로 연결하되 시선·축·위치·동작을 이어 준다. 인물 간 얼굴 변형을 정상적인 카메라 전환으로 처리하지 않는다.

연결용 자산 공유는 해당 버전의 장면 번호 안에서 설계한다. NOVEL의 N개 또는 웹툰의 선택 K개 Flow 작업에 시작+종료 모드를 쓰려면 두 실제 입력이 필요하다. 기존 선택 자산을 연결하거나 승인된 입력 준비를 별도 기록한다. 내부 키프레임이라는 이름으로 추가 생성 수를 숨기거나 기본 이미지 목록만 늘리지 않는다. 입력 자산을 준비할 수 없으면 지원되는 시작 프레임 모드와 컷 연결 계획을 검토한다.

연결 이미지가 같아도 중간 얼굴·몸·무기나 경계의 속도·방향이 맞는지 따로 확인한다. 첫·끝 프레임의 일치만으로 성공을 선언하지 않는다. 얼굴을 숨기는 구도나 스틸로 바꾸는 일을 액션 오류의 기본 해결책으로 삼지 않는다. 실제 캐릭터로 달리기·고개 회전·검술·표정 연기를 시험하고 실패 조건에 맞춰 샷을 수정한다. 선택한 영상 모델에서 그 실패가 발생한다고 시험 전에 단정하지 않는다.

## 생성과 검수

대표 제작 시험은 대사·표정과 연속 액션을 포함한다. 원본 얼굴과 시작/중간/끝 프레임, 동작 전환 순간을 대조하고 완성 클립을 재생한다. 얼굴 검사 자동화는 후보 선별용이며 유사도 점수만으로 통과시키지 않는다. 칼의 주인·수량·쥔 손·부상·복장, 접촉과 피격 결과도 대본과 맞춘다.

선택 키프레임을 바꾸면 그 키프레임을 사용하는 앞뒤 영상 작업을 무효화한다. 생성 중 깨진 얼굴을 새 캐릭터 정본으로 채택해 다음 영상에 누적 전파하지 않는다. 각 샷의 오류와 재생성 결과를 기록한다. 영상 제작 시험이 성공하기 전 연속성과 얼굴 보존을 보장하지 않는다.

원문에 피·신체 손상·처형·죽임·살육이 있어도 화면의 세부 묘사를 그대로 확대하지 않는다. 해당 사건을 전달하는 비노골적인 직전·직후의 시선·표정·거리·물건·반응 중 한 순간을 선택하고 원문 대응표에 해석을 남긴다. 낭독 원문과 인물의 실제 나이를 몰래 바꾸지 않는다. 간단한 긍정문으로 보이는 한 동작과 한 카메라를 지시하는 Flow 작성·실패 진단 기준은 [생성 정책](05_FLOW_EXECUTION.md)을 따른다.
