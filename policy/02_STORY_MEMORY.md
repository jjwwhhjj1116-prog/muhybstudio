# 서사 설계와 작품 기억

## 전면 재집필과 회차

시즌의 큰 사건·인물 관계·적의 계획·진실 공개 순서를 새로 설계한다. 이전 인수검토의 16회 배분은 비교 자료다. 좋은 기존 장면을 선택해 재사용할 수 있으나 원문 보존이 우선 목표는 아니다.

회차마다 인물의 당면 욕망, 이를 막는 상대의 행동, 선택의 결과와 다음 사건의 원인을 기록한다. 위기·관계 변화·통쾌함·여운의 배치는 사건에 따라 정한다. 매회 정해진 초에 반전을 넣거나 정해진 직접 대사로 열고 닫지 않는다. 고정 Hook/Intro/Body/Climax/End 표식은 문학 본문에서 제거하고 회차 편집 메타데이터로 관리한다. 1~15회는 실제 결과와 다음 사건을 이어 주고, 16회는 시즌 중심 갈등·관계·대가를 닫는다.

기술 청크는 회차 안의 완결된 장면/대화 경계로 나눈다. 상위 21개에 필요 시 하위 청크를 둔다. 글자 수나 전작 샷 수를 분량의 정답으로 삼지 않는다.

## 기억은 원문 근거가 있는 외부 파일

줄거리 요약은 찾기 위한 색인이다. 사실을 확정하는 근거는 버전이 명시된 설정·원고다. 기억을 채팅이 알아서 유지할 것으로 가정하지 않는다.

프로젝트별 memory에 다음을 둔다.

| 파일 | 기록할 내용 |
|---|---|
| canon.json | 새로 확정한 세계·인물 사실, 적용 시점, 원문 근거 |
| state.json | 현재 위치·시간·생존·부상·피로·무기·소지품·능력 대가 |
| knowledge.json | 인물별 아는 사실·오해·의심·모르는 사실, 획득 사건과 시점 |
| relationships.json | 상대별 신뢰·적의·욕망·숨긴 일·아직 풀리지 않은 감정과 변화 근거 |
| threads.json | 심은 단서·미해결 약속·회수 예정 범위·독자에게 공개된 정도 |
| events.jsonl | 실제 사건 순서, 서술 순서, 상태 변화, 원문 ID·해시 |
| issues.json | 충돌·누락·검토 의견, 근거, 상태, 적용한 수정과 재검수 |
| checkpoint.json | 마지막 확정 버전, 현재 회차/청크, 마지막 장면·다음 작업, 파일 해시 |

인물의 믿음은 세계의 사실과 분리한다. 독자가 아는 것, 작가만 아는 것, 각 인물이 아는 것도 분리한다. 미래 공개 정보는 계획 자료에 남기되 현재 인물의 지식으로 넘기지 않는다.

각 기억 항목은 id, scope, status, value, source_file, source_version, source_sentence_ids, valid_from, valid_until을 가진다. 모르는 값은 null/unknown으로 남긴다. 인물의 감정 해석처럼 확정하기 어려운 것은 observation/hypothesis로 구분한다. 계획은 planned, 검수 전 추출은 proposed, 확정 원고와 대조된 사실만 accepted다. 삭제·수정된 원문을 근거로 한 기억은 stale로 표시한다.

## 장면 전후의 처리

집필 전: 해당 장면의 인물·장소·소품으로 필요한 기억을 찾고, 마지막 완결 장면을 읽는다. 대화가 이어지면 마지막 두 문장만 잘라 읽지 않고 공방 전체의 필요한 범위를 읽는다. 과거 비밀·물건이 다시 등장하면 해당 근거 원문도 찾아 읽는다. 읽은 입력 버전과 장면 시작 상태를 저장한다.

집필 후: 초안의 사실 변화는 proposed로 추출한다. [인과 검수](03_REVIEW.md)를 통과한 원고 버전과 비교한 뒤 원고·기억·체크포인트를 같은 묶음으로 확정한다. 새 초안에 잘못 쓴 부상·소지품을 기억으로 덮어써서 정당화하지 않는다. 부분 저장이 실패하면 마지막 완전한 묶음에서 복구한다.

다음 집필에는 현재 장면과 관계없는 장부 전체, 옛 예문, 누적 검수 문구를 주입하지 않는다. 검색 결과가 없다고 사실이 없다고 단정하지 않으며, 결정적 단서·무공·과거 사건은 관련 원문까지 확인한다.

## 작품별 오류 기록

실제 작품의 모순과 수정 근거는 비공개 프로젝트의 memory/issues.json에 저장한다. 공개 지침에는 인물명·반전·결말·미공개 장면을 넣지 않는다.
