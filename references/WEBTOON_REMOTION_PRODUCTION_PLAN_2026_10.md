# 무협 웹툰판의 이미지·말풍선·모션 제작안

상태: 제작 방식 검토안 / 2026-10-09. 현행 workflow 3.2.0의 소설판과 웹툰판 구분을 따른다. 이 문서는 추천 구성과 구현할 항목을 정리한다. 편집 엔진 선택·설치·이미지 생성·TTS·파일럿 렌더는 아직 실행하지 않았다. 기존 작품과 NOVEL 제작 경로는 변경하지 않는다.

## 추천 구성과 선택 이유

웹툰판의 반복 제작은 **Codex 내장 이미지 생성 → 배역 음성 → Remotion 모션·말풍선 편집 → 청크 검수·회차 조립**으로 구성하는 것을 추천한다. CapCut은 필요한 최종 리듬·음악·수동 수정에 사용하고, Flow 영상은 선택한 훅·핵심 동작에서 검토한다. 화면 전체의 연속 인물 연기를 만드는 애니메이션과 정지 원화 중심의 모션 웹툰을 구별한다.

Remotion은 React 요소·이미지·SVG와 프레임별 값을 조합하는 도구다. 같은 말풍선·카메라·타이포 규칙을 데이터를 바꿔 반복 적용하기 좋다. 첫 전용 템플릿을 만드는 개발 시간은 필요하며 실제 제작 시간·렌더 속도·시청 효과는 파일럿 전에는 알 수 없다. 짧은 수동 시안은 익숙한 CapCut이 빠를 수 있지만 장편의 발화·좌표·수정 이력을 관리하려면 자동화 편집 데이터가 유리하다는 제작 판단이다. [Remotion 애니메이션](https://www.remotion.dev/docs/animating-properties), [이미지](https://www.remotion.dev/docs/img)

CapCut에는 현재 공식 [CapCut × Codex](https://www.capcut.com/tools/capcut-x-codex) 연결 안내도 있다. 대화로 클립·길이·텍스트 타이밍·음악을 수정하고 편집기를 여는 기능이 소개돼 있다. 수동만 가능한 도구라고 단정하지 않는다. 다만 이 세션의 플러그인 검색에는 결과가 없었고 설치·인증·장편 작업을 시험하지 않았다. 그 검색이 전체 배포 여부를 판정하지 않으며, 소개 페이지만으로 복잡한 말풍선 좌표·80분 무인 렌더·세 PC 재개가 확인된 것은 아니다.

## 제공된 영상과 갤러리에서 참고할 부분

[참고 영상](https://www.youtube.com/watch?v=7NBu5IW_2Xw)의 자동 한국어 자막에서 이미지·글자·도형의 코드 편집과 갤러리 활용 설명을 확인했다. 자동 자막은 오인식 가능성이 있으며 전체 영상의 시연을 직접 재현한 것은 아니다. [갤러리](https://www.aicitybuilders.com/remotion)는 브라우저에서 직접 열어 예제 목록, 41·42번 코드와 44번 설명을 확인했다.

| 예제 | 활용할 부분 | 무협판 조정 |
|---|---|---|

| 44 패럴랙스 | 전경·인물·배경의 서로 다른 이동 | 코드로 그린 예제 배경 대신 작품 원화의 레이어를 사용한다. 대화·위세·장소 소개에 선택해 적용한다. |

| 07 노이즈 / 08 경로 | 분위기 효과·선의 진행 | 안개·바람·검광에 의미가 있을 때 사용한다. 모든 화면을 흔들지 않는다. |

이는 위 예제를 그대로 복사하자는 제안이 아니다. 필요한 기능을 무협 전용 컴포넌트로 구성한다. 갤러리의 인물·사진·캐릭터는 사이트 소유라고 표시돼 있으므로 작품 자산으로 가져오지 않는다. 코드 공개를 이미지·브랜드 자산 사용 허가와 혼동하지 않는다.

## 이미지 생성과 캐릭터 유지

현재 세션에는 내장 이미지 생성·참조 편집 도구가 있다. Flow 이미지 생성이 필수는 아니다. 기존 한국 다크판타지 무협 웹툰 화풍과 승인 캐릭터 얼굴·머리·의복·무기·부상 상태를 참조해 생성한다. 새 작품의 인물은 먼저 확정 시트를 만든 뒤 장면 원화에 사용한다. [OpenAI Docs](https://learn.chatgpt.com/docs/image-generation)는 내장 이미지 생성이 일반 Codex 사용 한도에 포함된다고 안내한다. Flow 비용이 사라지는 만큼 이미지 생성 전체가 무제한 무료가 되는 것은 아니다.

공식 문서의 내장 기본 모델 안내와 실제 도구 호출에서 확인 가능한 실행 메타데이터를 구별한다. 현재 도구에는 명시적인 모델·quality 선택 인자가 없으므로 요청에 특정 이름·품질을 적은 것만으로 실제 해당 값이 실행됐다고 기록하지 않는다. 실제 결과·참조 일치·해상도·비율을 검수하고 공개되지 않은 실행 값은 미확인으로 남긴다.

자산은 장면별 필요에 따라 두 수준으로 준비한다.

- 일반 장면: 무문자 16:9 완성 원화. 같은 실제 이미지의 전체 구도·얼굴·손·소품 크롭을 편집한다.
- 레이어 연출이 필요한 장면: 배경판, 투명 인물, 필요한 전경이나 효과판. 인물 뒤 가려진 배경은 별도로 확보한다. 단순 분리만으로 가려진 그림이 생긴다고 가정하지 않는다.

말풍선·한글 문구·패널 테두리는 원화에 생성하지 않고 Remotion에서 별도로 그린다. 단순 크롭은 새 표정이 아니며 고개 회전·손동작·다른 표정은 실제 보조 그림이나 별도 연기 자산이 필요하다. 레이어를 이동시켜도 얼굴을 다시 생성하지 않는 장점이 있지만, 원화 자체의 얼굴 불일치·크롭 손상·잘못된 변형은 별도로 검수한다. 연속 검술·달리기·입모양 연기는 카메라 이동만으로 구현되지 않는다.

기본 원화·보조 자산·후보·재시도·재사용을 따로 집계한다. 레이어 경로에서도 N개의 승인 장면 합성 원화와 실제 생성된 레이어 파일 수는 구별해 기록한다. 파일별 원문 버전·scene_id·참조·생성 도구·실제 픽셀 크기·해시와 승인 상태를 비공개 작품에 남기고, 승인 파일을 재생성으로 덮어쓰지 않는다.

## 80분과 200장면의 의미

현행 기준은 한 공개 회차의 의미 장면 N≤200이다. N=기본 원화 수=장면별 모션 계획 수를 유지한다. 2~3문장은 초기 묶음이며, 시간·장소·사건의 전환과 실제 발화 시간을 함께 확인한다. 같은 의미 장면 안의 크롭·대화·반응 편집 컷 C, 실제 새 보조 그림 A, 말풍선 구간 B는 따로 기록한다. 새 시간이나 사건을 맡는 그림을 보조 자산으로 숨겨 N을 줄이지 않는다.

80분을 200장면으로 나누면 평균 24초다. 24초 내내 같은 얼굴을 확대하는 대신 실제 대화의 주도권과 반응에 따라 화면을 바꾼다. 다음은 연출을 설명하는 예시이며 고정 컷 수·길이 규칙이 아니다.

| 대화의 진행 | 화면의 역할 |
|---|---|
| 인물이 맞선 공간 확인 | 전체 구도로 거리·위치를 보여 줌 |
| 첫 발화 | 화자 쪽 재구도와 해당 말풍선 |
| 상대가 말을 듣고 판단 | 상대 반응 그림 또는 기존 그림에서 실제 보이는 반응 크롭 |
| 손이나 소품이 선택을 드러냄 | 해당 정보로 시선을 옮김 |
| 관계를 바꾸는 한마디 | 말풍선·표정에 집중하고 잠시 정지 |

정적인 기다림도 연출이다. 모든 이미지에 같은 줌, 계속되는 얼굴 흔들기, 주기적인 효과음·이모지를 적용하지 않는다. 80분을 채우려고 짧은 클립을 무한 반복하거나 침묵을 늘리지 않는다.

## 전용 템플릿의 최소 구성

다음 여섯 가지를 먼저 구현할 계획이다. 화풍·카메라·말풍선·폰트는 공통 테마로 관리하되 장면의 상황에 맞게 조합한다. 라이브러리 예제의 제품 광고·기술 발표 스타일을 작품에 주입하지 않는다.

1. **전체 장면:** 공간·거리·인물 배치와 제한된 카메라 이동.
2. **대화 공방:** 두 사람의 시선·화자 전환·말풍선 교대. 한 화면의 대사가 서로 경쟁하지 않게 구성.
3. **반응과 침묵:** 실제 표정 자산과 읽을 수 있는 정지 시간. 대사 없이도 선택의 결과를 보여 줌.
4. **짧은 충돌:** 준비 자세·검광·충격·결과 그림과 소리. 실제 연속 검술을 구현했다고 표시하지 않음.
5. **위세와 기연:** 거리·구도·주변 인물의 반응·선택한 타이포로 격과 발견을 드러냄.
6. **시간·장소 전환:** 필요한 나레이션과 짧은 전환. 문장마다 장면을 새로 만들지 않음.

인물의 움직임은 비율을 보존하는 제한된 위치·카메라 변화부터 사용한다. 조선식 복식·임의 페이지 가장자리·생성 글자·워터마크 등 기존 시각 검수는 유지한다. 의도한 편집 패널 구획은 생성 오류 테두리와 구별한다.

## 성우·말풍선·모션을 연결하는 순서

1. 공통 이야기와 웹툰판 원고를 검수·잠근다. 대사는 기존 `[화자명|감정]"대사"` 형식을 유지한다. 나레이션 설명을 그대로 등장인물 입에 옮기지 않는다. 편집 지시는 별도 데이터에 둔다.
2. 의미 장면을 먼저 나누고 원문 범위·장면 상태·발화 ID를 연결한 뒤 이미지·모션 계획을 만든다. 기존 시각화 3줄 입력과 원문 내부 빈 줄 금지를 유지한다.
3. 배역별 고정 성우로 음성을 만들고 실제 청취·길이·발화 시각을 확정한다. TTS 요청 한 개를 대사 한 줄로 강제하지 않는다. 동일 원고·보이스·연기 조건만 재사용한다.
4. 실제 음성에 말풍선·카메라·반응·효과를 맞춘다. 말풍선 꼬리는 해당 화자를 가리키고 얼굴·손·중요 소품을 가리지 않는다. 긴 대사는 의미 구간으로 나눠 원문과 순서를 보존한다.
5. 기본 대사는 음절마다 타이핑하지 않고 읽을 수 있는 단위로 표시한다. 분노·외침·중요한 이름·초식 같은 포인트에서만 타이포를 강화한다. 별도 하단 자막에 같은 대사를 중복 표시하지 않는다.
6. 본문 말풍선에는 읽기 쉬운 한글 폰트를, 타이틀·초식에는 작품에 맞는 별도 서체를 검토한다. 서체 사용권·글자 측정·줄바꿈·최소 읽기 크기는 실제 출력 프레임에서 확인한다. 긴 글을 무조건 축소하지 않고 발화 구간을 나눈다.

[Remotion Callout](https://www.remotion.dev/docs/shapes/callout)은 SVG 말풍선의 크기와 꼬리 방향·위치를 제공한다. 한글 레이아웃·얼굴 가림 검사·음성 정렬은 제작 구현이 필요하다. [Audio](https://www.remotion.dev/docs/media/audio)는 타임라인에 음성을 넣는 기능이며 감정 성우·발화 정렬 자체를 자동 완성하는 기능은 아니다.

## 편집 데이터와 부분 재개

구현할 웹툰 편집 매니페스트에는 아래 정보를 둔다. 지금의 Flow 추출기 입력과 혼동하지 않는다.

| 데이터 | 연결할 정보 |
|---|---|
| 작품·버전 | 공통 정본, WEBTOON_EXPERIMENT, 원고 해시, 공개 회차·내부 부 |
| 장면 | scene_id, 원문 범위, 기본 이미지·보조 자산, 캐릭터 상태, 지속 시간 |
| 발화 | utterance_id, 화자, 감정, 원문, voice_id, 음성 파일·해시, 실측 시작·끝 |
| 편집 컷 | scene_id 안의 cut_id, 사용 자산·크롭 영역, 카메라·레이어, 전역 정수 프레임 |
| 말풍선·효과 | 발화 ID, 실제 표시 문구·시각·좌표·꼬리·읽기 영역, 효과음·타이포 |
| 선택 Flow | 원래 scene_id와 승인 파일·검수 상태. 사용하지 않으면 K=0 |
| 렌더 | 해상도·fps·폰트·편집 버전·의존 해시·청크 경계·출력·QA 상태 |

말풍선 위치만 바뀌면 해당 편집 청크를 다시 렌더하고 이미지·TTS를 불필요하게 재생성하지 않는다. 원고가 바뀌면 관련 발화·정렬·장면·청크를 다시 검토한다. 대사 중간에 기술 청크 경계를 강제로 넣지 않는다. 고정 fps·전역 프레임을 기준으로 BGM·효과음·말풍선의 경계를 처리한다.

## 렌더와 실제 검수

첫 구현은 16:9, 1920×1080, 30fps의 3~5분 파일럿을 추천한다. 대화 공방·짧은 나레이션·반응·짧은 충돌을 함께 넣어 읽기 속도와 스타일을 비교한다. 본편은 우선 2~5분 기술 청크로 렌더·검수·재개하며 내부 약20분 부와 공개 약80분 회차는 별도 단위다. 정확한 청크 길이는 실제 자산과 PC 성능에 맞춘다.

30fps의 80분 회차는 144,000프레임이다. 로컬 렌더 시간·동시 처리량·메모리는 실제 파일럿으로 측정한다. [Lambda](https://www.remotion.dev/docs/lambda)의 권장 범위는 Full HD에서80분 미만이므로 정확한80분 목표를 단일 Lambda 작업으로 보장하지 않는다. [청크 결합](https://www.remotion.dev/docs/renderer/combine-chunks)은 공식 문서도 오용 시 오디오·영상 결함을 경고하는 고급 API다. 단순 이어붙이기로 무결성이 확보됐다고 가정하지 않는다.

구조 검수: 원문·화자·대사 순서·해시·장면 누락·파일·정수 프레임·시간 겹침을 확인한다. 시각 검수: 말풍선 잘림·얼굴 가림·꼬리 방향·한글 깨짐·자산 경계·화풍을 실제 프레임에서 본다. 청취·재생 검수: 모든 청크의 발화·감정·음성 동기와 조립 경계를 확인한다. 최종 전체 디코딩·실측 시간·누락·검수 기록 후 납품하며, 공개 회차별 최종 실측은4,800초 이상이어야 한다. 샘플 프레임이나 자체 점수만으로80분 완성본을 통과시키지 않는다.

CapCut에 완성 MP4를 넣어 손질할 경우 이미 합성된 말풍선·인물 레이어가 각각 편집 가능한 트랙으로 자동 복원되는 것은 아니다. 텍스트 수정은 Remotion 원본에서 다시 렌더하거나 별도 레이어 교환 경로를 구현한다. CapCut에서 최종 수정한 구간도 편집 로그·출력 해시·재검수로 남긴다.

## 비용과 현재 구현 상태

Remotion의 [현행 라이선스](https://www.remotion.pro/license)는 개인과3명 이하 기업의 상업 영상 제작을 무료로 허용한다. 무료 자격과 별개로 이미지·TTS 생성, PC·저장·전력, 선택한 클라우드 실행비는 남는다. 200 기본 원화만 세고 실제 보조 자산·재시도를 비용에서 누락하지 않는다. 웹툰판의 대사가 늘어나면 해당 성우 사용량도 달라질 수 있다. 생성비·낭독 시간·렌더 시간은 실제 파일럿 후 예산에 반영한다.

현재는 조사·제작안이다. 전용 React 컴포넌트·원화·음성·편집 매니페스트 추출기·렌더·CapCut 연결은 만들지 않았다. 내장 이미지 경로를 실제 선택하면 다음을 정리해야 한다.

- 공통 캐릭터 승인과 Flow 사용 장면의 캐릭터 등록을 분리한다. Flow K=0 경로에 등록을 자동으로 강제하지 않는다.
- 이미지 생성 도구, 선택 영상 제공자, 편집 엔진을 별도 필드로 관리한다. 내장 도구의 미확인 모델·품질 값을 임의로 확정하지 않는다.
- 기존 Flow 전용 추출기는 보존하고 웹툰 편집표·발화 정렬·모션 매니페스트용 추출기와 검증기를 별도로 구현한다. 가짜 영상 프롬프트로 입력 요건을 채우지 않는다.
- 실제 승인 자산으로 전용 템플릿을 구현·렌더·청취 검수한다. 이 제안의 문서 테스트를 미디어 제작 완료로 보고하지 않는다.

공통 제작안과 도구만 공개 Git으로 공유한다. 작품 원고·인물·이미지·음성·편집표·계정 정보는 비공개 작품에 보관한다.
