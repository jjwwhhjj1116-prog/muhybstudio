# Google Docs 누적 작성 계약

## 대상 확인

쓰기 전에 문서 ID, 전체 탭 제목·순서·중첩, 현재 개정, 목표 탭을 읽는다. `?tab=t.0`은 열린 탭일 뿐 전체 문서 범위를 뜻하지 않는다.

## 같은 문서 원칙

사용자가 하나의 Docs에 쓰라고 하면 새 문서를 만들지 않는다. 기존 대본을 보존하고 같은 문서 안에 다음 구조로 누적한다.

1. 대본
2. 캐릭터시트
3. 시각화 프롬프트
4. Flow
5. 영상 프롬프트
6. 제목·설명란·썸네일

탭 추가 기능이 지원되면 단계별 탭을 우선하고, 지원되지 않으면 명확한 최상위 제목으로 같은 탭에 이어 붙인다.

단, Google Docs 파일 전체 용량은 탭을 추가해도 우회되지 않을 수 있다. 예상 누적치가 `workflow/11_DOCUMENT_CAPACITY.md`의 위험 기준을 넘으면 첫 시각화 쓰기 전에 용량 계획을 확정한다. 이미 한계에 도달한 뒤에는 기존 내용을 무단 축약하지 않는다.

## 청크 쓰기

- 청크 하나당 별도 쓰기 요청
- 쓰기 직후 해당 범위를 다시 읽어 말미, 장면 번호, 누락 여부 검증
- 다음 청크 시작 전에 체크포인트 저장
- 전체 문서 덮어쓰기 금지

## 실패

쓰기 결과를 읽어 확인하지 못하면 성공으로 기록하지 않는다. 커넥터 오류 후 중복 삽입 가능성이 있으면 마지막 고유 표식과 장면 번호를 먼저 확인한다.

`FAILED_PRECONDITION` 발생 시 요청을 절반으로 줄여 1회 진단한다. 한 장면 단위도 반복 실패하면 용량 차단으로 판정하고 `workflow/11_DOCUMENT_CAPACITY.md`의 연속 문서 절차로 전환한다.
