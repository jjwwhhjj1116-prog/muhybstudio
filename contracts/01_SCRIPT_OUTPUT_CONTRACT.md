# 대본 출력 계약

- UTF-8. 본문은 한국어 소설형 낭독 나레이션과 `[화자명|감정]"대사"`를 함께 담는다. 일반 서술을 비낭독 지문으로 분리하지 않는다.
- 감정 목록·FIRM 제한·문체는 [현행 집필 지침](../policy/01_WRITING.md)을 따른다. 예시에 태그가 없어도 새 직접 대사에는 태그를 붙인다.
- 제목 및 Hook·Intro·Body·Climax·End 구분을 유지한다. 회차형은 공개 회차 전체에 한 벌, 단일 장편은 작품 전체에 한 벌을 적용한다. 신작 내부 네 부를 합쳐 공개 한 화로 쓰며 내부 부·기술 청크 경계에서 구조·요약·CTA·엔딩을 재시작하지 않는다. 내부 챕터 표식은 요청 시 본문 밖의 편집 자료로 관리한다.
- `[CTA]`는 Hook 뒤, `[END]`는 End 직전에 두는 무음 제작 표식이다. 본문에 구독·좋아요 요청을 추가하지 않는다. 두 표식은 발화·장면 수에 포함하지 않는다.
- Hook·Intro의 첫/끝을 무조건 직접 대사로 만드는 범용 규칙은 철회했다. 해당 구간은 나레이션 시작·체언 종결·반문·행동의 여운도 가능하다. 사용자가 특정 작품의 문장을 위치까지 잠갔다면 그 잠금을 따른다.
- 공개 회차 End의 마지막 발화는 반드시 `[화자명|감정]"대사"`다. 대사 뒤에 낭독 나레이션을 붙이지 않는다. 중간 공개 회차는 현재 사건에 근거한 의문·위협·결단 등으로 다음 회차의 기대를 남긴다. 최종 공개 회차는 전체 약속과 관계를 마무리하는 직접 대사로 끝내며 새로운 후속편 떡밥을 의무로 만들지 않는다. 이 요건을 Hook·Intro나 내부 부의 자유로운 연결부에 확대 적용하지 않는다.
- 청크 요청일 때만 `[청크 NN/전체수]`를 붙이고 전체수는 확정된 기술 집필 계획을 따른다. 16부·공개 4화·기술 청크 수는 별개다. 청크 수 미정은 관리 파일에 null로 남기며 임의로 21개를 할당하지 않는다. 공개 회차 요청은 완성 회차로 제공한다.
- 공백 포함 본문 글자 수와 실제 발화 글자 수는 관리 보고서에 산출 기준을 밝혀 기록한다. 관리 장부·계획·검수표·영상 지시를 낭독 본문에 섞지 않는다.
