납품은 제작 버전과 공개 회차를 식별한다. 기본 `NOVEL`은 기존 무협소설, `WEBTOON_EXPERIMENT`는 신규 무협웹툰 실험이며 같은 이야기의 정본을 공유해도 승인 원고·해시·분할·프롬프트·편집·제목 자료는 분리한다. 기존 작품을 새 계약으로 자동 변경하지 않는다.

- NOVEL: 시각화 N장면=이미지 N개=Flow 영상 N개, 동일한 1~N 번호, 공개 한 화 N≤200.
- WEBTOON_EXPERIMENT: 시각화 N장면=기본 이미지 N개=모션 편집 계획 N개, 동일한 1~N 번호, 공개 한 화 N≤200. 훅·핵심 장면에서 선택한 Flow K개(K≤N)는 원래 장면 번호·ID를 유지한다. 비선택 장면의 빈 항목이나 1~K 재번호로 수량을 꾸미지 않는다.

내부 후보·공유 키프레임·생성 재시도는 납품 장면 수와 구별한다. 번호 없는 후속 생성 컷을 추가하지 않는다. 웹툰의 장면 안 크롭·표정 참조 재사용·오버레이와 실제 새 반응 그림은 구별해 자산·원문 대응·생성 수량·해시를 기록한다. 원문을 새 장면에 배정하면 해당 버전의 모든 기본 목록·선택 영상 목록을 함께 갱신하며 전체 원문과 200 상한을 재검수한다. 둘을 함께 충족할 수 없으면 사용자 조정 필요를 기록한다. 구문서를 새 지침과 함께 적용하지 않는다. 이전 내용은 Git 이력에 보존되어 있다.

현행 네 단계 절차와 Python 원문 추출: [workflow/13_SCRIPT_TO_PROMPTS.md](../workflow/13_SCRIPT_TO_PROMPTS.md). 이미지·TTS가 없으면 영상과 시간 지시는 DRAFT다. 검수된 영어 이미지 필드를 그대로 추출하고, Flow 영상은 실제 입력에 맞는 비노골적인 한 동작·시선·표정과 한 카메라를 짧은 긍정문으로 작성한다. 완료 행동 반복·임의 발화·긴 부정 목록을 넣지 않는다. 별도 TTS를 쓰면 조용한 움직임으로 지시한다. 제한 대응은 원문을 바꾸거나 실제 나이를 바꾸는 우회가 아니며 성공을 보장하지 않는다.

8초 생성 클립과 최종 표시 시간을 구분한다. 8초×200개는 26분 40초이므로 약 80분은 이미지·편집 계획과 실측 TTS·최종 영상으로 따로 확인한다. 웹툰은 선택 K개의 생성 길이만 합산한다. 자동 연장·3배 감속·무한 반복으로 시간 충족을 보고하지 않는다. 추출기 실행·파일 해시·문서 준비는 실제 생성·참조 첨부·음성·최종 편집 검수의 완료를 뜻하지 않는다.
