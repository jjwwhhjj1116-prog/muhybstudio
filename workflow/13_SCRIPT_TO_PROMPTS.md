# 대본에서 Flow 프롬프트까지

사용자가 정한 제작 순서는 1단계 대본 → 2단계 캐릭터시트 → 3단계 장면 분석·시각화 → 4단계 Flow 이미지·영상 프롬프트다. 내부 stage_status의 세부 단계와 구별하며, 문서 완성을 실제 생성 완료로 표시하지 않는다.

## 제작 버전과 새 공개 편성

기본 `NOVEL`은 기존 **무협소설 버전**, `WEBTOON_EXPERIMENT`는 신규 **무협웹툰 실험 버전**이다. 같은 이야기를 두 방식으로 제작하며 기존 방식을 교체하지 않는다. 세계관·인물·주요 인과·결말은 공통 정본을 사용하되 버전별 승인 대본·해시·장면표·프롬프트·편집 계획·제목·설명란을 분리한다. 같은 장면 번호가 다른 버전의 동일 입력이라는 뜻은 아니다. 공통 자산은 실제 파일·해시·참조 역할을 연결해 재사용한다.

다음 신작은 내부 16부·각 약 20분, 네 부씩 공개 총 4화·각 약 80분·4,800초로 계획한다. 각 제작 버전의 시각화는 공개 한 화 전체 N≤200이다. 기존 승인 작품의 편성·대본·자산·잠금은 자동으로 변경하지 않는다. 웹툰은 캐릭터·시각화 뒤 전체 장면의 모션 편집 계획을 만들고 훅·핵심 장면 중 필요한 일부만 Flow 영상 작업으로 진행한다.

## 1. 대본

policy/01_WRITING.md와 contracts/01_SCRIPT_OUTPUT_CONTRACT.md를 따른다. 일반 서술은 낭독 나레이션이며 직접 대사는 화자·감정·큰따옴표를 보존한다. 세계관 명칭을 바꾸면 소속·직위·조직의 기원·인과도 함께 검토한다. 무협의 익숙한 세력 체계를 사용하되 문파 구성과 서열은 작품별 정본에서 정한다. 명칭만 같다는 이유로 다른 작품의 설정을 가져오지 않는다.

신작은 policy/07_SYNOPSIS_AND_RELEASE_PLAN.md와 비공개 synopsis/release_plan.json에서 내부 16부·공개 4화·기술 청크 범위를 읽는다. 공개 회차의 네 부를 하나의 원고로 연결해 개선·확정한다. 부분 파일 저장을 공개 회차 전체 확정으로 표시하지 않는다. 기존 작품은 기존 사용자 계획과 잠금을 유지한다.

검토한 원고의 버전·해시와 발화 원문을 고정한다. 이후 영상 길이나 장면 수에 맞추려고 원문을 조용히 다시 쓰지 않는다. 수정이 필요하면 새 대본 버전과 영향받는 후속 산출을 기록한다.

기본 흐름은 초안 작성·자체 검수 → 사용자 초안 열람 → 글쓰기 개선 → 확정이다. 글쓰기 개선은 policy/03_REVIEW.md에 따라 문장 연결·인물다운 발화·나레이션의 감정과 전체 흐름을 다듬고 설정을 재대조한다. 일괄 진행 등 사용자가 정한 범위가 우선이며 추가 승인 절차를 만들지 않는다. 이 단계의 실행 기록과 개선 원고는 비공개 작품에 둔다.

## 2. 캐릭터시트

설정집과 해당 회차에서 나이·인상·머리·의상·소속·무기·쥔 손·부상·감정 표현·변장·회상 상태를 정리한다. 원문에 없는 디자인 선택은 제작 제안으로 표시한다. 반복 등장하는 단역도 식별한다. 회상 인물과 현재 인물, 이름 없는 아이와 후반의 주요 인물을 임의로 합치지 않는다.

공개 한 화에 들어가는 네 부 전체의 인물과 지속 상태를 확인한다. 부가 바뀐다는 이유로 부상·복식·무기·감정을 초기화하지 않는다. 이미 잠근 디자인은 재사용하며 실제 상태 변화가 있는 파생만 분리한다.

이 단계는 텍스트 준비에 그치지 않는다. 실제 캐릭터시트 이미지를 만들고 대상 Flow 프로젝트에 업로드한 뒤, 시각화 프롬프트의 한글 캐릭터명과 동일한 이름으로 등록하고 저장 결과를 확인한다. 기존 확정 이미지가 있으면 재사용한다. 실제 파일이 없으면 참조 경로·해시를 비워 두며 등록 완료라고 보고하지 않는다. 세부 완료 기준은 stages/07_CHARACTER_IMAGE.md를 따른다.

## 3. 장면 분석 후 시각화

해당 제작 버전 원문에 sentence_id와 정확한 위치를 부여하고, 사건·장소·시간·행동의 연속성을 먼저 분석한다. 같은 순간을 이어가는 약 2~3문장을 초기 의미 묶음으로 잡고 짧은 호명과 반응은 함께 담을 수 있다. 한 문장마다 자동으로 새 장면을 만들지 않는다. 먼저 원문 소유권·범위·분할 이유가 있는 장면표를 저장하고 누락·중복을 확인한 뒤 영어 시각화를 작성한다. 실제 TTS가 없으면 시간 계획은 예상이고 실제 입력 이미지가 없으면 영상 지시는 DRAFT다.

장면마다 원문, 등장인물·상태, 배경, 표정과 행동의 이유, 카메라, 시작 자세, 중간 행동, 종료 자세, 다음 연결 방식을 쓴 뒤 영어 프롬프트를 작성한다. 여러 묶음으로 나눠 작성해도 원문 소유권과 앞뒤 상태를 이어받는다. 문장 수를 줄이려고 서로 다른 장소·시간을 하나의 그림에 겹치지 않는다.

공개 한 화 전체가 200장면을 넘으면 같은 장소·시간·이어지는 행동의 인접 묶음을 의미가 유지되는 범위로 통합하고 2~3문장보다 늘어난 이유를 기록한다. 전체 원문·한 이미지의 단일 순간·200 상한을 함께 충족할 수 없으면 충돌 구간·필요 장면 수·가능한 조정안을 남긴다. 원문 삭제·요약·거대한 문장 재작성으로 해결하거나 사용자 조정 없이 200을 초과한 완성본을 납품하지 않는다.

전체 원문 포함·중복 여부와 장면별 의미 검토를 구분한다. 기계 검사는 인과나 연기의 자연스러움을 판정하지 않는다. 검수에서는 무기 인계, 발도·납검, 족쇄 해제, 부상, 젖은 옷, 상처 방향, 시선과 이동 축이 되돌아가지 않는지 확인한다. 연결 샷은 이전 종료 keyframe_id를 다음 시작에 공유한다. 카메라 전환이 필요한 장면은 CUT으로 명시한다.

구체적인 문화·화면 기준: 중국 강호 배경에 맞는 복식·건물·무기를 사용한다. 조선시대 갓·삿갓과 조선 관복, 만화책 페이지 끝단·패널 테두리·분할 격자가 생기는 연출은 금지한다. 생성 프롬프트는 단일 화면이 가장자리까지 이어지는 배경과 적절한 복식을 긍정문으로 설명한다. 금지 대상을 길게 나열하다가 오히려 시트·만화 페이지 구도를 유도하지 않는다. 실제 그림 검수에서도 이 항목을 확인한다.

두 버전의 기본 생성 이미지는 깨끗한 16:9 단일 화면이다. 웹툰의 판넬 경계·말풍선·타이포는 후편집 오버레이로 관리하며 원치 않는 만화책 페이지 테두리가 생성되는 것과 구별한다. 편집 구도·좌표·모션·말풍선·음성 기술 설명은 낭독 원고에 넣지 않는다. 동일 대사를 말풍선과 자막에 중복 노출하지 않고 실제 편집 화면에서 한국어 글자·화자·읽는 순서·가독성·얼굴 가림을 검사한다.

원문에 노골적인 피·신체 손상·처형·죽임·살육이 있어도 해당 사건의 비노골적인 직전·직후 표정·시선·반응 중 한 순간을 화면으로 고르고 대응표에 남긴다. 낭독 원문·실제 나이·인과·부상 지속 상태는 보존한다. 고유명 반복보다 실제 참조 연결을 먼저 확인하며 제한 발생 시 프롬프트·이미지·음성·할당량·모델/기능·서비스 원인을 나눠 본다. 이는 단어 삭제만으로 모더레이션을 우회하는 방식이나 오류 없는 생성 보장이 아니다.

이 단계는 내부 06_SHOT_PLAN의 텍스트 준비다. 음성 정렬과 실제 프레임 검사 전에는 타이밍·시각 QA 완료가 아니다.

## 납품 장면 수와 번호

- NOVEL: 시각화 N장면=이미지 N개=Flow 영상 N개, 모두 같은 1~N 번호다.
- WEBTOON_EXPERIMENT: 시각화 N장면=기본 이미지 N개=모션 편집 계획 N개, 모두 같은 1~N 번호다. Flow 영상은 훅·핵심 장면에서 선택한 K개(K≤N)만 원래 장면 ID·번호로 작성한다. 1~K로 재번호하거나 빈 영상 항목으로 N개를 꾸미지 않는다. K 미정·계획 K·실제 생성 및 QA 통과 수를 구별한다.

다음 신작은 두 버전 모두 공개 한 화 N≤200이다. 시각화 밖 후속 A/B/C 생성으로 수량을 숨기지 않는다. 추가 분할이 필요하면 해당 버전 원문을 새 시각화 장면에 중복 없이 배정하고 모든 기본·선택 목록을 함께 개정해 상한을 재검수한다. 웹툰의 장면 안 크롭·승인 표정 참조 재사용과 새 반응 그림은 원문 대응·자산 ID·해시·생성 여부·수량·비용으로 구별한다. 새 사건·시간을 장면 안에 숨기지 않으며 좌우 반전으로 손·부상·흉터를 바꾸지 않는다. 내부 식별자와 재시도는 보존하지만 장면 상한의 예외로 쓰지 않는다.

1~N 번호는 공개 회차 전체에서 이어진다. 내부 부·기술 청크의 원문 ID와 공개 장면 번호를 별도 대응표에 보존한다. 부별 분할을 합친 뒤에도 같은 원문을 두 번 배정하거나 부 사이 내용을 빠뜨리지 않는다. 긴 파일은 검토 묶음으로 나눌 수 있으나 최종 통합본과 세 목록의 전체 수량·순서·원문 범위까지 대조한다. 제목·설명란·타임라인도 이 공개 회차 ID와 대본 버전을 사용한다.

## 생성 길이·표시 시간·웹툰 모션 계획

현재 Flow 영상 초안은 Veo 3.1 - Lite·8초를 출발값으로 삼으며 실제 계정 UI의 모델·입력 모드·지원 길이·비용을 확인한다. 8초 생성 길이와 같은 장면의 최종 표시 시간은 다르다. 4,800초/200장면은 평균 24초이며 약 20~30초 구간은 참고로만 쓴다. 모든 장면의 길이를 강제하거나 확정 대사를 삭제·급하게 낭독시키지 않는다.

8초×200클립은 1,600초·26분 40초여서 약 80분 전체를 연속 생성 움직임으로 채우지 못한다. NOVEL은 같은 이미지 유지·크롭·리프레이밍과 필요한 클립을 원문·실측 음성에 맞게 배치한다. 웹툰은 선택 K개의 생성 길이만 합산하고 나머지를 포함한 모든 장면에 표정·반응·크롭·타이포·말풍선·성우 음성의 모션 편집 계획을 둔다. 컷과 말풍선 수를 N에 강제로 맞추지 않는다. 기존 참조 재사용과 새 자산 생성, 모션 계획과 실제 편집 결과를 구별한다.

자동 Extend·일률적인 3배 감속·무한 반복을 기본값으로 쓰지 않는다. 별도 생성·연장이 필요하면 원문 대응·수량·추가 비용·편집 영향을 검토해 사용자 조정 뒤 새 계획을 사용한다. 실제 이미지·TTS·편집·재생 검수 전에는 타이밍이나 약 80분 최종 영상 완료라고 보고하지 않는다.

## 4. 정확한 추출과 실제 프레임 반영

현행 도구는 automation/export_scene_prompts.py다. 장면 분석과 영어 집필은 검토된 입력 bundle에서 끝내고 Python은 확정 필드를 그대로 추출한다. 레거시 변환기는 사용하지 않는다. 아래 도구의 고유 키프레임 출력은 내부 자료이며, 그것만으로 납품 1:1 계약을 충족했다고 판단하지 않는다. 사용자용 이미지·영상 목록은 시각화 번호 기준으로 별도 대조·검수한다.

도구 입력과 출력은 제작 버전별로 분리한다. 기존 추출기 실행만으로 웹툰의 선택 K개 영상·전체 N개 모션 편집·말풍선 렌더가 구현됐다고 판단하지 않는다. 웹툰 선택 Flow 목록은 검수 필드와 원래 장면 ID를 보존해 전체 분할표의 부분 목록으로 대조하며 비선택 장면을 빈 영상 작업으로 만들지 않는다.

    python automation/export_scene_prompts.py PRIVATE_BUNDLE.json PRIVATE_SCRIPT.md PRIVATE_OUTPUT

출력 위치는 공개 clone 밖이어야 한다. 입력은 sentences, scenes, shots, keyframes 및 script_sha256을 포함한다. 필드 계약과 최소 실행 예시는 도구 및 tests/test_prompt_export.py를 참조한다. 입력 문장 목록 자체가 원고 전체인지도 별도 확인해야 한다. 추출기는 전달된 목록 안의 원문 위치·장면 소유권·순서를 검사한다.

- 04_Flow_images.md: 첫 사용 순서의 고유 키프레임 이미지 프롬프트.
- 04_Flow_starts.md / 04_Flow_ends.md: 샷 순서의 시작·종료 프롬프트. 공유 프레임을 다시 생성하라는 작업 목록이 아니다.
- 04_Omni_video_DRAFT.md: 실제 시작·종료 이미지와 TTS를 확인하기 전의 동작 초안.
- 04_prompt_index.json: 원문·입력·출력 해시, 문구 위치, 샷과 키프레임 대응.

원문 해시 불일치, 중복·누락·순서 오류, 잘못된 공유 프레임, 바뀐 출력 덮어쓰기를 거부한다. 재출력할 때 기존 수정본은 보존하고 새 버전 폴더를 사용한다. --require-assets는 실제 자산 파일·해시의 존재만 검사한다. 얼굴·동작·프레임 내용이나 지원 모델을 검증하는 옵션이 아니다.

위 Omni 파일명은 현행 도구의 호환 출력명이며 Omni 실행 선택이나 10초 지원을 뜻하지 않는다. 실제 모델·길이·제작 버전은 입력·색인에서 확인한다. 장면별 영상은 실제 시작 순간에 맞는 비노골적인 한 동작·시선·표정과 한 카메라를 짧은 긍정문으로 작성하며 완료 행동 반복·임의 발화·긴 부정 목록을 넣지 않는다. 별도 성우 TTS를 쓰면 조용한 움직임으로 지시한다.

이미지 생성·선택 뒤 선택 모드의 실제 입력 그림을 보고 영상 초안을 수정한다. 시작+종료 모드는 양 끝을 대조하며 시작 이미지 단독 모드에는 종료 자산을 억지로 요구하지 않는다. 선택 자산 해시와 음성 길이를 연결하고 policy/05_FLOW_EXECUTION.md에 따라 생성·회수·중간 프레임 QA를 진행한다. 텍스트 추출기의 구현은 Chrome 확장 프로그램이나 전체 영상 자동화의 완성을 뜻하지 않는다.
