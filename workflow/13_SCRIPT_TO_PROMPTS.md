# 대본에서 Flow 프롬프트까지

사용자가 정한 제작 순서는 1단계 대본 → 2단계 캐릭터시트 → 3단계 장면 분석·시각화 → 4단계 Flow 이미지·영상 프롬프트다. 내부 stage_status의 세부 단계와 구별하며, 문서 완성을 실제 생성 완료로 표시하지 않는다.

## 1. 대본

policy/01_WRITING.md와 contracts/01_SCRIPT_OUTPUT_CONTRACT.md를 따른다. 일반 서술은 낭독 나레이션이며 직접 대사는 화자·감정·큰따옴표를 보존한다. 세계관 명칭을 바꾸면 소속·직위·조직의 기원·인과도 함께 검토한다. 무협의 익숙한 세력 체계를 사용하되 문파 구성과 서열은 작품별 정본에서 정한다. 명칭만 같다는 이유로 다른 작품의 설정을 가져오지 않는다.

검토한 원고의 버전·해시와 발화 원문을 고정한다. 이후 영상 길이나 장면 수에 맞추려고 원문을 조용히 다시 쓰지 않는다. 수정이 필요하면 새 대본 버전과 영향받는 후속 산출을 기록한다.

## 2. 캐릭터시트

설정집과 해당 회차에서 나이·인상·머리·의상·소속·무기·쥔 손·부상·감정 표현·변장·회상 상태를 정리한다. 원문에 없는 디자인 선택은 제작 제안으로 표시한다. 반복 등장하는 단역도 식별한다. 회상 인물과 현재 인물, 이름 없는 아이와 후반의 주요 인물을 임의로 합치지 않는다.

텍스트 시트와 실제 참조 이미지는 별개다. 기존 웹툰 디자인을 유지하며 실제 파일이 없으면 참조 경로·해시를 비워 둔다. 모델에 첨부했는지도 별도 기록한다. 이 단계는 내부 04_CHARACTER_REFERENCES의 텍스트 준비에 해당한다.

## 3. 장면 분석 후 시각화

원문에 sentence_id와 정확한 위치를 부여하고, 사건·장소·시간·행동의 연속성을 먼저 분석한다. 10초당 약 두 문장을 출발점으로 묶되 짧은 호명과 이어지는 반응은 함께 담을 수 있다. 실제 TTS 길이와 동작을 확인하기 전에는 생성 길이와 최종 편집 길이를 확정하지 않는다.

장면마다 원문, 등장인물·상태, 배경, 표정과 행동의 이유, 카메라, 시작 자세, 중간 행동, 종료 자세, 다음 연결 방식을 쓴 뒤 영어 프롬프트를 작성한다. 여러 묶음으로 나눠 작성해도 원문 소유권과 앞뒤 상태를 이어받는다. 문장 수를 줄이려고 서로 다른 장소·시간을 하나의 그림에 겹치지 않는다.

전체 원문 포함·중복 여부와 장면별 의미 검토를 구분한다. 기계 검사는 인과나 연기의 자연스러움을 판정하지 않는다. 검수에서는 무기 인계, 발도·납검, 족쇄 해제, 부상, 젖은 옷, 상처 방향, 시선과 이동 축이 되돌아가지 않는지 확인한다. 연결 샷은 이전 종료 keyframe_id를 다음 시작에 공유한다. 카메라 전환이 필요한 장면은 CUT으로 명시한다.

구체적인 문화·화면 기준: 중국 강호 배경에 맞는 복식·건물·무기를 사용한다. 조선시대 갓·삿갓과 조선 관복, 만화책 페이지 끝단·패널 테두리·분할 격자가 생기는 연출은 금지한다. 생성 프롬프트는 단일 화면이 가장자리까지 이어지는 배경과 적절한 복식을 긍정문으로 설명한다. 금지 대상을 길게 나열하다가 오히려 시트·만화 페이지 구도를 유도하지 않는다. 실제 그림 검수에서도 이 항목을 확인한다.

이 단계는 내부 06_SHOT_PLAN의 텍스트 준비다. 음성 정렬과 실제 프레임 검사 전에는 타이밍·시각 QA 완료가 아니다.

## 4. 정확한 추출과 실제 프레임 반영

현행 도구는 automation/export_scene_prompts.py다. 장면 분석과 영어 집필은 검토된 입력 bundle에서 끝내고 Python은 확정 필드를 그대로 추출한다. 레거시 변환기는 사용하지 않는다.

    python automation/export_scene_prompts.py PRIVATE_BUNDLE.json PRIVATE_SCRIPT.md PRIVATE_OUTPUT

출력 위치는 공개 clone 밖이어야 한다. 입력은 sentences, scenes, shots, keyframes 및 script_sha256을 포함한다. 필드 계약과 최소 실행 예시는 도구 및 tests/test_prompt_export.py를 참조한다. 입력 문장 목록 자체가 원고 전체인지도 별도 확인해야 한다. 추출기는 전달된 목록 안의 원문 위치·장면 소유권·순서를 검사한다.

- 04_Flow_images.md: 첫 사용 순서의 고유 키프레임 이미지 프롬프트.
- 04_Flow_starts.md / 04_Flow_ends.md: 샷 순서의 시작·종료 프롬프트. 공유 프레임을 다시 생성하라는 작업 목록이 아니다.
- 04_Omni_video_DRAFT.md: 실제 시작·종료 이미지와 TTS를 확인하기 전의 동작 초안.
- 04_prompt_index.json: 원문·입력·출력 해시, 문구 위치, 샷과 키프레임 대응.

원문 해시 불일치, 중복·누락·순서 오류, 잘못된 공유 프레임, 바뀐 출력 덮어쓰기를 거부한다. 재출력할 때 기존 수정본은 보존하고 새 버전 폴더를 사용한다. --require-assets는 실제 자산 파일·해시의 존재만 검사한다. 얼굴·동작·프레임 내용이나 지원 모델을 검증하는 옵션이 아니다.

이미지 생성·선택 뒤 실제 양 끝 그림을 보고 영상 초안을 수정한다. 선택 자산 해시와 음성 길이를 연결하고 policy/05_FLOW_EXECUTION.md에 따라 생성·회수·중간 프레임 QA를 진행한다. 텍스트 추출기의 구현은 Chrome 확장 프로그램이나 전체 영상 자동화의 완성을 뜻하지 않는다.
