# 11. Google Docs 용량 사전검사와 연속 문서

## 목적

장편 대본, 캐릭터시트, 800장 이상 시각화 프롬프트를 한 Google Docs에 누적하면 Docs의 문자·구조 한계에 도달할 수 있다. 이 검사는 작성 도중 `FAILED_PRECONDITION`이 발생해 기존 내용을 축약하거나 일부 장면을 누락하는 사고를 막는다.

## 쓰기 전 필수 산출

시각화 프롬프트 생성 직후, Google Docs 첫 쓰기 전에 다음 값을 매니페스트에 기록한다.

- 대본 문자 수와 UTF-8 바이트 수
- 캐릭터시트 문자 수
- 시각화 전체 문자 수와 장면 수
- Flow 전체 예상 문자 수
- 영상 프롬프트 전체 예상 문자 수
- 메타데이터 예상 문자 수
- 문서 누적 예상치
- 장면당 평균·최대 문자 수
- 안전 여유율 20%를 적용한 배치 계획

## 판정

- Docs의 실제 허용량은 계정·문서 구조·공백 비율에 따라 API가 먼저 거절할 수 있으므로 고정 숫자 하나를 성공 보장값으로 취급하지 않는다.
- 예상 누적치가 700,000자를 넘거나 시각화가 600장 이상이면 `HIGH_CAPACITY_RISK`로 표시한다.
- `HIGH_CAPACITY_RISK` 상태에서는 본문 쓰기를 시작하기 전에 저장 구조를 확정한다.

## 안전한 저장 구조 우선순위

1. 사용자가 반드시 한 Docs를 요구하고 예상치가 수용 범위 안이면 단계별 탭으로 작성한다.
2. 한 Docs가 물리적 한계를 넘으면 같은 Drive 폴더에 `본편 제작 1`, `본편 제작 2` 연속 문서를 만들고 첫 문서에 다음 문서 링크와 장면 경계를 기록한다.
3. 사용자가 외부 파일을 허용하면 전체 원문 `.txt`·`.jsonl`을 정본으로 저장하고 Docs에는 인덱스·검수표·링크를 둔다.

## 금지

- 용량을 만들기 위해 이미 확정된 대본·장면·캐릭터 앵커를 임의 삭제하지 않는다.
- 사용자가 승인하지 않은 상태에서 기존 프롬프트의 화풍·연속성·금지 조건을 일괄 축약하지 않는다.
- 새 탭이 문서 전체 한계를 우회한다고 가정하지 않는다.
- `FAILED_PRECONDITION` 뒤 같은 대형 요청을 반복하지 않는다.

## 실패 후 최소 복구

1. 마지막 정상 장면 번호와 다음 장면 미삽입 여부를 읽어 확인한다.
2. 원인을 요청 크기, 리비전 충돌, 문서 전체 용량으로 분리한다.
3. 한 장면 쓰기도 지속 실패하면 `DOCUMENT_CAPACITY_BLOCKED`로 고정한다.
4. 기존 본문 변경이 필요한 경우 변경 문구, 영향 장면 수, 보존되는 의미를 사용자에게 제시하고 명시적 승인을 받는다.
5. 승인 없이 가능한 대안은 연속 문서 또는 외부 정본 링크뿐이다.

## 체크포인트 필드

```json
{
  "document_capacity": {
    "status": "OK | HIGH_CAPACITY_RISK | DOCUMENT_CAPACITY_BLOCKED",
    "estimated_total_chars": 0,
    "last_verified_scene": 0,
    "next_scene": 1,
    "continuation_document_id": null,
    "mutation_approval_required": false
  }
}
```
