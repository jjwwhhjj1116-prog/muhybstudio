# 02. 스크립트 작성·글쓰기 개선·검수 지침

이 문서는 무협스튜디오 현행 3.2.0의 집필 정책·대본 출력 계약·검수 기준을 기능별로 정리한 사용본이다. 2026-10-09 사용자가 승인한 압축 10안 중 대본 개선 7~10을 반영했다. 별도 진단 문서의 12안 번호와 혼용하지 않는다. 기존 승인 설정·대본·사용자 잠금은 보존한다. 작품 원문과 사용자 예시 원문은 수록하지 않는다.

이하의 소설형 나레이션 중심 기준은 기존 NOVEL에 적용한다. 신규 WEBTOON_EXPERIMENT 집필은 [웹툰판 사용본](02B_WEBTOON_SCRIPT_WRITING.md)과 [전용 정책](../policy/09_WEBTOON_WRITING.md)을 선택한다. 공통 형식·정본·공개 편성은 유지하고 두 사용본을 중복 주입해 소설형 비중을 웹툰에 강제하지 않는다.

## 1. 집필 입력과 범위

이번 공개 회차의 시놉시스, 관련 세계관·인물·무공 설정 원문, 내부 부 배분, 직전 완결 장면과 현재 상태, 사용자가 정한 잠금을 먼저 읽는다. 요약만으로 결정적 단서·과거 사건·무공을 판단하지 않는다. 이어지는 대화는 공방의 필요한 범위까지 읽는다.

연결된 사용자 문체 원문과 해설은 별도 자료로 읽고 참고 범위를 기록한다. 사용자가 직접 다듬어 선호한다고 지정한 구간을 가장 중요한 문체 근거로 삼는다. 수정이 덜 된 후반까지 같은 모범으로 확대하지 않는다. 해당 자료가 없으면 읽었다고 주장하지 않는다.

신작은 내부 16부·부당 약 20분을 1~4부·5~8부·9~12부·13~16부씩 공개 1~4화로 묶는다. 두 제작 버전 각각 공개화 목표는 80분(4,800초), 전체 목표는 320분이다. 목표·예상 낭독·실제 TTS·최종 렌더의 길이는 구별한다. 내부 부와 기술 집필 청크는 공개 회차가 아니다. 청크는 작업량과 완결된 장면·공방 경계로 계획하며 21개를 강제하지 않는다. 공개 회차를 요청받으면 완성 회차를 제공한다.

집필 전에 ‘무협소설(기존)’(`NOVEL`)인지 ‘무협웹툰(신규 실험)’(`WEBTOON_EXPERIMENT`)인지 작업 범위를 확인한다. 공통 시놉시스·정본의 핵심 선택·결과·관계·결말을 유지하고 원고 해시·부·문장·장면 매핑은 버전별로 분리한다. 두 버전을 한 원고에 섞거나 실험을 이유로 기존 원고를 덮어쓰지 않는다. 자세한 계약은 [두 버전 제작 정책](../policy/08_TWO_VERSION_PRODUCTION.md)을 따른다.

아래 소설형 나레이션 기준은 기존 무협소설의 기본값이다. 무협웹툰 실험은 인물의 현장 상호작용·표정·성우 공방·말풍선 전달을 중심으로 쓰고 나레이션은 공간·시간 전환, 시야 밖 사건, 무공의 격, 보이지 않는 심정 등 필요한 이해·정서를 보완한다. 원소설 설명을 그대로 대사로 바꾸거나 배역에게 작가 해설을 시키지 않는다. 대사 비율은 고정하지 않는다.

두 낭독 원고 모두 `[화자명|감정]"대사"`와 공개 마지막 직접 대사를 유지한다. 일반 서술은 낭독 대상이며 비낭독 표정·모션·카메라·말풍선 연출은 별도 자료다. 원고를 전부 영상 각본으로 전환하지 않는다. 전체 유료 생성 전에 동일 이야기 구간의 3~5분 파일럿 비교를 권장하되 새로운 승인 관문으로 만들지 않는다.

## 2. 소설형 나레이션과 영화체 호흡

무협소설을 읽어 주되 화자는 감정을 가진 영화의 동행자다. 인물의 명성·위세·격의 차이, 의리와 원한, 압도와 반격을 듣는 사람이 느끼게 한다. 담백함은 불필요한 설명을 덜어내는 뜻이지 장중함과 감정의 축적을 없애는 뜻이 아니다.

나레이션이 상황을 열고 기대와 긴장을 쌓는다. 앞의 사건이 다음 행동·생각·대사를 낳게 하며, 사건의 진행과 중요한 감정이 함께 이어지도록 쓴다. 상황을 전부 나열하거나 같은 설명으로 되돌아가지 않는다. 이름·정체·위협·상실을 체감할 호흡은 남긴다. 모든 문장을 동작 보고로 바꾸지 않는다.

마침표는 의미와 감정을 끊고 쉼표와 연결어미는 다음 이미지나 반응으로 이끈다. 이어지는 행동을 같은 길이·강세로 하나씩 끊지 않는다. 이름·정체·결정타에는 짧게 힘을 줄 수 있고, 체언 종결·질문·반문·현재형은 화자의 태도와 장면에 맞게 사용한다. 이를 순서대로 반복하는 문법 공식으로 만들지 않는다.

‘다’를 금지하지 않는다. 어미만 바꾸거나 억지 존댓말을 섞지 않는다. 문단의 호흡, 대사 전후의 기다림, 같은 정보의 반복을 함께 판단한다. 긴 문장이 자연스럽게 이어지는 경우도 살린다. 구두점이 실제 성우 음성에서 원하는 쉼을 만드는지는 음성 단계에서 확인한다.

설명은 지금 상황을 이해하거나 위험·격·기대·감정을 느끼게 할 이유가 있을 때 남긴다. 앞으로 필요한 정보는 사건과 충돌하는 시점에 배치하고 이미 전달한 내용을 다시 해설해 힘을 빼는 구간은 덜어낸다. 묘사가 공간을 열고 위세·불안·상실을 쌓으면 유지한다. 이름·정체·경지·문파의 장중한 소개도 이유가 있으면 살리며 긴 설명을 전부 금지하거나 모든 정보를 행동으로 바꾸지 않는다. 인물이 아직 모르는 반전을 화자가 미리 정답처럼 단정하지 않는다. 드러난 욕망과 절박함을 담백하게 직접 서술할 수 있으며 감정을 반드시 물리적 몸짓으로만 우회할 필요는 없다.

승패와 큰 말 뒤에 누구의 신뢰·적의·미련·판단이 달라졌고 다음 말이나 행동에 어떤 흔적이 남는지 확인한다. 장면이 바뀌었다고 감정을 초기화하지 않는다. 짧은 서술·기다림·하지 않은 말도 반응이 될 수 있으며 눈물·몸짓·반응 대사를 매번 넣지 않는다.

사람이 자연스러운 주어인 곳에서는 사람을 주어로 쓴다. 풍경·소리·물건·신체가 중심인 순간에는 그것을 주어로 쓸 수 있다. 뜻이 통하지 않는 비유, 번역투, 헛된 추상어, 귀에 거슬리는 중복은 문맥으로 고친다. 어휘를 바꾸다 지칭 대상과 인과가 흐려지면 원래 명칭을 유지한다.

## 3. 대사는 포인트 훅으로 쓴다

대사는 상황·인물·감정을 드러내고 위협·도발·보호·원망·결단·궁금증을 만드는 순간 사용한다. 말 한 줄씩 모두 절정으로 만들 필요는 없다. 공방이 뒤의 한마디를 준비한다면 준비와 반응을 포함한 장면 전체의 효과로 판단한다. 강함을 논하거나 풍문을 다투는 대화도 현재 목적과 반응이 있으면 유지한다.

중요한 대사에서는 화자가 누구로부터 무엇을 얻고, 무엇을 막거나 숨기려 하는지 상대의 다음 반응과 함께 읽는다. 처지·관계가 달라도 같은 명언이나 해설이 통한다면 발화를 다시 검토한다. 태그를 잠시 가려 말과 문맥에도 감정이 있는지 볼 수 있으나 최종 태그·큰따옴표는 보존한다. 공방을 한 줄로 줄이거나 모든 대사를 과장하지 않는다.

의미 없는 문답, 끝난 설명의 반복, 모든 행동을 입으로 중계하는 말은 줄인다. 대사 수나 비율을 목표로 만들지 않는다. 대사가 너무 적어 인물의 존재감과 상황의 힘이 사라지는지도 본다. 주요 초식의 직접 발화와 준비·위력은 필요한 결정타에 살린다.

사람의 냄새는 처지·욕망·관계에서 나온다. 지금 이 사람이 이 상대에게 할 법한 말인지 읽는다. 모든 인물이 같은 명언이나 줄거리 설명을 말하지 않게 한다. 감정은 태그뿐 아니라 말 자체에도 드러나야 한다. 나레이션에도 망설임·미련·분노·애정 등 상황에서 생긴 감정이 배어 있어야 한다. 감정어와 몸짓을 일괄 추가해 해결하지 않는다.

## 4. 바꾸지 않는 대본 형식

| 항목 | 현행 출력 기준 |
|---|---|
| 본문 | 한국어 소설형 낭독 나레이션과 직접 대사를 한 대본에 담는다. 일반 서술은 성우가 읽는다 |
| 직접 대사 | 반드시 `[화자명|감정]"대사"`. 화자명은 작품의 정확한 고정명이다 |
| 큰따옴표 | 실제 직접 대사에만 사용한다 |
| 감정 | 내추럴·화남·슬픔·기쁨·행복·놀람·FIRM |
| FIRM | 남자 주인공의 결의·핵심 응답·결정적 초식에만 사용한다 |
| 구조 | 제목, Hook·Intro·Body·Climax·End를 유지한다. 공개 회차 전체에 한 벌이다 |
| CTA | `[CTA]`를 Hook 뒤에 두는 무음 제작 표식이다 |
| END | `[END]`를 End 직전에 두는 무음 제작 표식이다 |
| 표식 처리 | CTA·END는 발화나 장면 수로 세지 않는다. 본문에 구독·좋아요 요청을 추가하지 않는다 |
| 본문 밖 자료 | 카메라·음향·영상 프롬프트·비낭독 연기 지문·관리 장부·검수표·글자 수는 별도 자료로 둔다 |
| 저장 | UTF-8. 원고의 버전과 원문을 고정하고 관리 보고서에 글자 수 산출 기준을 밝힌다 |

내부 부나 청크마다 Hook·Intro·이전 요약·CTA·End를 재시작하지 않는다. 요청받은 내부 챕터 표식은 낭독 본문 밖 편집 자료로 관리한다. 청크 요청일 때만 `[청크 NN/전체수]`를 사용하고 전체수는 확정 집필 계획을 따른다. 수량 미정은 관리 자료에 미정으로 남긴다.

Hook·Intro의 첫 문장과 끝 문장은 장면 효과에 따라 선택한다. 범용적으로 직접 대사 위치를 강제하지 않는다. 사용자가 특정 작품의 대사와 위치를 잠갔다면 그 잠금은 유지한다.

## 5. 공개 회차 엔딩

공개 회차 End의 마지막 발화는 반드시 `[화자명|감정]"대사"`다. 그 뒤에 설명·풍경·다음 행선지를 정리하는 낭독 나레이션을 붙이지 않는다. 이 요건을 Hook·Intro나 내부 부의 연결부에 확대하지 않는다.

중간 공개 1~3화는 현재 사건에서 생긴 의문·위협·결단·관계 변화로 다음 회차의 기대를 남긴다. 최종 공개 4화는 중심 갈등·관계·대가를 회수한 뒤 인물다운 마지막 대사로 마무리한다. 끝난 이야기에 새 후속편 떡밥을 의무로 붙이지 않는다. 따옴표를 붙인 줄거리 요약이나 막연한 예고로 끝내지 않는다. 근거 없이 새로운 진실을 확정하거나 회수할 수 없는 단서를 엔딩에 추가하지 않는다.

## 6. 예시를 참고하는 방법

예시에서 기대를 쌓는 나레이션, 부딪치는 주장, 기준을 뒤집는 한마디, 행동 뒤의 감정이 힘을 얻는 이유를 읽는다. 첫 등장·액션·비극 등 이번 장면의 기능에 맞게 적용한다.

문장·인물·지명·능력·사건·전개 순서를 옮기지 않는다. 이름만 바꾼 복제나 매번 같은 회상 액자를 만들지 않는다. 예시에 감정 태그가 없어도 새 직접 대사에는 태그를 붙인다. 오타와 인과 오류까지 복제하지 않는다. 예시는 문체 근거이며 이번 작품 설정집이 아니다.

## 7. 집필·개선·확정 순서

초안 작성·자체 검수 → 사용자 초안 열람 → 글쓰기 개선 → 확정으로 진행한다. 사용자가 이미 일괄 진행이나 확정을 지시했다면 이 순서를 이유로 단계마다 재승인을 요구하지 않는다.

집필 전에 현재 장면에서 무엇이 궁금해지고 어느 말·행동에 감정이 터지는지 잡는다. 관련 설정, 직전 문맥, 현재 상태, 이번 범위를 읽어 직렬로 이어 쓴다. 부·청크 경계에서 재소개·요약·가짜 엔딩을 만들지 않는다. 문장·공방·공격과 결과를 분량 때문에 중간에서 자르지 않는다.

글쓰기 개선은 의견만 전달하는 일이 아니라 개선 원고를 새 버전으로 작성하는 작업이다. 먼저 핵심 선택·상대 반응·결과·보상의 시놉시스 근거와 이를 구현한 본문 구절을 대조한다. 빠진 전환점이나 해설로만 건너뛴 결정을 보완한 뒤 문장·호흡을 다듬는다. 사건 설계가 비어 있으면 해당 기획 범위를 보완하며 새 사실은 제안으로 분리한다. 모든 이동·회상·내적 결단을 긴 장면으로 늘리지 않는다.

문장 하나를 매끈하게 바꾸기 전에 앞뒤 문단을 읽는다. 원인과 반응이 빠진 연결은 접속사를 추가하는 것만으로 해결하지 않는다. 인물의 감정·인지가 초기화되거나 급변하는 이유를 확인한다. 대표 문단을 소리 내어 읽어 같은 정보·구조·강세·종결이 반복되는지 본다. 해당 음성이 있으면 실제 문단을 대조하고 기존 보이스 샘플을 미생성 문단의 청취 통과 근거로 쓰지 않는다.

갑작스러운 결론, 문맥 밖 추상 해설, 뜻이 어긋난 비유, 모호한 지칭, 반복 요약, 인물에 맞지 않는 대사를 실제 구절에서 찾아 고친다. ‘AI스럽다’를 탐지 점수나 금칙어로 판정하지 않는다. 모든 긴 문장을 짧게 잘라 같은 박자로 만들거나 어미만 교체하지 않는다.

개선 뒤 공개 회차 전체와 연결부를 읽고 행동·무기·소지품·부상·인지·감정을 설정 원문과 다시 대조한다. 부분 검수만으로 전체 검수를 대신하지 않는다. 정상 구간까지 무조건 다시 쓰거나 새 사건·능력·반전을 임의로 추가하지 않는다. 새 사실이 필요하면 제안과 영향을 따로 기록한다.

## 8. 필수 형식·설정 검수

- 화자 고정명, 감정 목록과 FIRM 사용, 태그·큰따옴표의 누락·오류.
- 일반 나레이션의 비낭독 지문 전환, 관리·연출 정보를 본문에 섞은 부분.
- 제목·구조·CTA·END·작품 잠금의 누락과 중복.
- 공개 End의 마지막 직접 대사와 이후 낭독 나레이션 유무.
- 사건의 원인·결과, 인물의 지식·오해·거짓말, 부상·무기·소지품·이동 시간·능력 비용.
- 부 경계의 중복 설명·요약·CTA·종결, 감정·인지의 초기화, 해결된 갈등의 이유 없는 재시작.
- 중간 회차의 기대와 최종 회차의 중심 약속·관계·대가 회수.

초안에서 추출한 변화는 제안 사실이다. 검수한 원고와 대조한 뒤 원고·기억·확정 지점을 함께 갱신한다. 초안의 잘못된 부상·소지품으로 정본을 덮어쓰지 않는다.

## 9. 재미·발화·낭독 검수

형식 오류와 문학적 효과는 구분한다. 아래 다섯 관점을 실제 장면·문단과 근거 구절로 검토한다.

1. 진행과 기대: 사건·위협·의문·격·감정이 쌓이는가. 위세를 세우는 기다림과 변화 없는 지연을 구분했는가.
2. 포인트 대사: 상황·인물·감정·궁금증을 만드는가. 준비 공방이 필요한가. 너무 많아 힘이 흩어지거나 너무 적어 인물이 사라지지 않았는가.
3. 귀의 호흡: 같은 길이·강세·종결로 끊기지 않는가. 쉼과 연결이 의미를 따르는가. 소설체와 맞지 않는 어미를 억지로 섞지 않았는가.
4. 자연스러운 발화와 서술: 처지·관계에 맞는 말인가. 감정이 태그에만 있지 않은가. 비유·지칭·번역투와 미리 폭로한 사실을 점검했는가.
5. 감정과 예시 독립성: 중요한 말·행동 뒤에 감정이 남는가. 즉시 해설로 힘을 빼지 않았는가. 예시의 사건·문장을 복제하거나 검수로 장중함을 지우지 않았는가.

먼저 설정·인과·형식을 읽고 다음으로 재미·발화·호흡을 읽는다. 문제 범위를 고친 뒤 영향받은 구간을 다시 확인한다. 실제 문제와 수정 이유를 남기고 사용자에게 개선본과 핵심 변경을 제공한다. 이유 없는 전체 재작성 루프나 근거 없는 만점 판정을 만들지 않는다.

## 10. 점수를 요청받았을 때

현행 기본 편집 척도는 인과·설정 25, 진행·기대 25, 인물·감정·포인트 대사 20, 낭독 호흡·자연스러운 연결 20, 복선·회수·회차 엔딩 10점이다. 같은 척도로 개선 전후를 평가하며 각 항목에 근거·약점·수정 결과를 붙인다. 형식 오류는 점수와 별도로 해결한다.

90점 이상을 요청받으면 낮은 항목의 구체적 약점을 고친 뒤 다시 평가한다. 숫자만 올려 개선을 대신하지 않는다. 점수는 편집자의 판단이며 흥행 지표나 실제 청취 검증이 아니다. 위세·원한·기연·대결·의리·비밀·관계의 일곱 재미 관점도 중심 약속과 실제 효과로 읽되 모든 부에 전부 넣는 조건으로 바꾸지 않는다.

## 11. 분량과 후속 제작

부당 약 20분·공개화 목표 80분을 설명 반복, 문장·대사 수 증가, 침묵이나 불필요한 느린 낭독으로 채우지 않는다. 부별 사건의 비중에 따라 예상 분량은 조정할 수 있다. 대본의 예상 길이와 실제 음성·최종 영상의 실측 길이를 구분하고 목표와 차이가 생기면 기록한다. 음성과 겹치는 영상 시간은 두 번 더하지 않는다. 아직 듣지 않은 TTS를 청취 통과로 기록하지 않는다.

확정 원고의 버전과 원문을 고정한 뒤 캐릭터시트와 장면 분할로 넘어간다. 각 버전의 신작 공개화당 시각화 200장면 이내다. 무협소설은 시각화 N=이미지 N=영상 N, 무협웹툰 실험은 시각화 N=기본 이미지 N=모션 구간 N에 선택 Flow 영상 K개를 원래 장면 ID로 연결한다. 약 2~3문장은 초기 의미 묶음이지 집필 문장 수나 문장 길이 기준이 아니다. 8초 생성 클립과 20~30초 안팎의 편집 구간은 별개로 확인한다. 장면 상한·클립 길이를 맞추려고 낭독 원문을 삭제·축약하지 않는다. 수정이 필요하면 새 원고와 영향을 받는 제작 자료를 함께 기록한다.

## 이 사용본에서 새 규칙으로 추가하지 않은 것

무조건 짧게 쓰기, 문장 50자 제한, ‘다’ 종결 금지, 어휘·쉼표·느낌표 횟수표, 대사 비율과 개수 할당, 모든 문장에 감정어 추가, 모든 감정을 몸짓으로만 표현하기, Hook·Intro 특정 대사 위치 강제, 소설을 영상 각본으로 바꾸기, 예시 문장·사건 복제는 새 기준으로 추가하지 않았다. 옛 금지표도 첨부하거나 재적용하지 않는다. 승인된 압축 개선 7~10은 본문에 통합했으며 긴 제안 목록을 매 청크마다 주입하지 않는다.
